# 낚시 게임(`fishing`) + 지속형 게임 틀(`world`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** onlyfms에 세이브가 이어지는 성장형 낚시 게임을 넣고, 그 기록 3종을 프로필에 띄운다.

**Architecture:** 플랫폼에 세 번째 게임 종류 `world`를 추가한다(등록부, `/world/:game`, Edge Function `world`, 테이블 `world_saves`). 게임은 순수 함수 `WorldLogic`(상태 + 행동 → 새 상태)만 내고, 서버가 세이브 행을 잠근 트랜잭션 안에서 그 로직을 돌린다. 프로필 기록은 manifest `records` + 테이블 `game_records`로 게임과 무관하게 구동한다.

**Tech Stack:** Vite + React 18 + TypeScript, vitest, Supabase(Postgres, RLS, Edge Function/Deno, postgres.js), Canvas 2D (새 의존성 없음).

**Spec:** `docs/superpowers/specs/2026-11-23-fishing-design.md`

## Global Constraints

- 플랫폼 코드(`src/platform/`, `src/app/`, `supabase/functions/world/`)에 게임 id 분기 금지. 게임마다 다른 점은 manifest·등록부·`WorldLogic`으로 푼다.
- `src/games/**/logic.ts`, `data.ts`, `manifest.ts`는 순수 함수·외부 의존 없음, 상대 import에 `.ts` 확장자 명시 (Deno가 import한다). React를 import하지 않는다.
- Deno 코드 import는 상대 경로, `npm:`, `node:`만.
- 화면 문구는 전부 한국어, 모바일 우선. 캔버스 밖 색은 `theme.css` 토큰만. 캔버스 내부는 자체 팔레트.
- 원작 게임의 이미지를 추출·모사하지 않는다. 그래픽은 전부 새로 그린다.
- DB 변경은 `npx supabase@2 migration new <이름>`으로 만든 마이그레이션 파일로만.
- 새 npm 의존성을 추가하지 않는다.
- 커밋 메시지 `type: 내용`. 푸시 전 `npm test && npm run typecheck && npm run build`. main 직접 푸시 금지, 작업 브랜치 → PR.
- 게임은 `hidden: true`로 낸다.
- PR 경계: **PR 1** = Task 1~5 (`feat/world-platform`), **PR 2** = Task 6~8 (`feat/fishing-logic`), **PR 3** = Task 9~11 (`feat/fishing-ui`).

## Review Focus

1. **두 탭에서 동시에 판매**: 같은 사용자의 `sell` 두 요청이 동시에 와도 골드는 한 번만 오른다 (세이브 행 `for update`). → Task 3
2. **resolve 응답 유실 후 재시도**: 서버는 이미 처리했는데 응답을 못 받고 다시 보내면 `no_pending`이 온다. 화면은 오류로 멈추지 않고 `load`로 다시 맞춘다. → Task 10
3. **로직 버전이 오른 뒤의 옛 세이브**: 필드가 빠진 옛 state를 `migrate`가 기본값으로 채우고, 골드·도감은 보존한다. → Task 7, Task 3
4. **이상한 payload**: `power`가 NaN·음수·2, `tier`가 문자열·소수, 없는 `area`. 상태는 바뀌지 않고 오류 코드만 돌려준다. → Task 7
5. **탭이 백그라운드에 갔다 옴**: `requestAnimationFrame`이 멈췄다가 큰 `dt`가 한 번에 들어와도 물고기가 순간이동하거나 게이지가 한 프레임에 바닥나지 않는다 (`dt` 상한). → Task 8

```ts
export type WorldCtx = { now: number; rng: () => number }
export type WorldRecord = { key: string; value: number; detail?: string }
export interface WorldLogic<State, Action, View> {
  version: number
  init(): State
  /** 옛 버전 state를 현재 형식으로. 모르는 값은 기본값으로 채우고 던지지 않는다 */
  migrate(state: unknown, fromVersion: number): State
  apply(state: State, action: Action, ctx: WorldCtx): { state: State; result?: unknown } | { error: string }
  view(state: State, ctx: { now: number }): View
  records(state: State): WorldRecord[]
}
export type WorldModule = { manifest: Manifest; logic: WorldLogic<any, any, any> }
```

### Task 3: Edge Function `world`

**Files:**
- Create: `supabase/functions/world/index.ts`, `handler.ts`, `handler.test.ts`, `deno.json`(duel 것과 동일 내용)
- Modify: `scripts/fn-test.sh` (루프에 `world` 추가)

**Interfaces:**
- Consumes: Task 1 `getWorld`, `WorldLogic`; Task 2 테이블; `../_shared/db.ts`의 `Sql`, `txOn`, `createSql`
- Produces:

```ts
export type WorldDeps = {
  sql: Sql
  now: () => number
  getUserId(req: Request): Promise<string | null>
  rng: () => number            // index.ts는 crypto.getRandomValues 기반으로 넣는다
  registry?: { getWorld(id: string): WorldModule | undefined }
}
export function handle(req: Request, deps: WorldDeps): Promise<Response>
```
  요청 본문: `{ game: string, action: 'load' }` 또는 `{ game: string, action: 'act', payload: unknown }`
  성공 200: `{ view: unknown, result: unknown | null, server_now: number }`
  오류: 401 `unauthorized` / 403 `not_approved` / 404 `unknown_game`(없는 게임, 또는 숨김인데 관리자 아님) / 400 `invalid_action` `{ message }` (형식 오류, payload JSON 2048자 초과) / 400 `{ error: <logic이 돌려준 코드> }`
- 동작 규칙:
  - 승인·관리자 여부 조회와 숨김 판정은 `duel/handler.ts`의 `Me` 조회 방식을 그대로 따른다.
  - 매 요청 한 트랜잭션. `world_saves` 행을 `insert … on conflict do nothing` 뒤 `select … for update`.
  - 행이 방금 생겼으면 `logic.init()`. `logic_version`이 현재와 다르면 `logic.migrate(state, logic_version)` 결과를 쓰고 버전을 갱신 (load에서도 저장).
  - `act`: `logic.apply(state, payload, { now, rng })`. `error`면 아무것도 쓰지 않고 400. 성공이면 state 저장 후 `logic.records(state)`를 `game_records`에 upsert.
  - `logic.apply`가 던지면 500 `internal`, 저장 없음.
  - `index.ts`는 `duel/index.ts`와 같은 구조(CORS, JWT 확인)에서 브로드캐스트·`PLAY_SECRET`만 뺀다.

- [ ] **Step 1: 실패하는 테스트 작성** (`duel/handler.test.ts`의 DB 연결·사용자 생성 헬퍼 방식. 등록부는 `deps.registry`로 가짜 world를 넣는다: Task 1의 `testWorld`와, 버전 2에서 `{ n, bonus }`로 migrate하는 변형, apply가 던지는 변형, 숨김 변형). 테스트 이름과 단정:
  - `load creates a save with init state` → view `{ n: 0 }`, `world_saves` 1행, `logic_version` 1
  - `act applies and persists` → inc 두 번 뒤 load view `{ n: 2 }`
  - `act upserts records` → `game_records`에 `(user, game, 'n', 2)`
  - `logic error changes nothing` → `{ type: 'bad' }` → 400 `nope`, state 그대로
  - `throwing logic returns 500 and rolls back`
  - `version bump migrates on load` → 버전 1로 저장된 `{ n: 3 }`을 버전 2 로직으로 load → `{ n: 3, bonus: 0 }`, `logic_version` 2
  - `concurrent acts do not lose updates` → 같은 사용자 inc 10개를 `Promise.all` → n === 10 **(Review Focus 1)**
  - `saves are per user` → A의 inc가 B의 view에 영향 없음
  - `unauthorized / not_approved / unknown_game / hidden game for non-admin / oversized payload / missing action` 각각 상태 코드와 error 코드
