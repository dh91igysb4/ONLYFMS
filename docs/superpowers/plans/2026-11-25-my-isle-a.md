# 내 섬 A단계 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (또는 subagent-driven-development) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사람마다 섬 하나(모양 2종 중 선택)를 주고, 마을 선착장 목적지 창으로 내 섬·친구 섬을 오가며, 친구 섬은 구경만 하게 한다.

**Architecture:** 낚시 게임 안에 지역 `isle`을 더하고, 섬 맵은 고른 모양(`isle.layout`)으로 정한다. 장소는 "지역 + 주인"이고, 주인이 있는 장소는 실시간 방 키가 `isle-<주인 id 32자>`다. 친구 섬은 플랫폼 `world` 함수의 새 요청 `visit`(쓰지 않음, `publicView`만)와 새 RPC `world_players`로 받는다.

**Tech Stack:** TypeScript/React, vitest, Deno(world 함수), Postgres(pgtap).

**Spec:** `docs/superpowers/specs/2026-11-25-my-island-design.md` §5

**시작 조건:** "낚시터 어종 다양화"가 main에 머지된 뒤 그 main에서 브랜치를 새로 딴다(설계 §6). 그때 `logic.version`은 그 시점 값 + 1(어종 다양화 뒤 19 → 20, 신발·여러 마리 버리기 PR이 20·21을 먼저 써서 실제로는 22).

## Global Constraints

- 문구 한국어, 모바일 우선. 캔버스 내부 색 예외, 그 밖은 theme 토큰.
- 플랫폼(`src/platform/**`, `supabase/functions/world/`, 새 RPC)은 게임 id를 보지 않는다.
- `logic.ts`·`data.ts`·`maps/**`·`isle.ts`는 순수(React·DOM 없음), 상대 import `.ts`.
- `logic.version` +1, migrate 테스트, `world` 재배포. DB는 `npx supabase@2 migration new world_players`로만.
- 이름: 내 섬 **"내 섬"**, 남의 섬 **"{아이디}의 섬"**, 이름을 못 찾으면 **"누군가의 섬"**. 낚시 지역 `island`("섬")는 그대로.
- 섬 모양 2종: id `crescent`(초승달 섬), `twin`(쌍둥이 만 섬). 고르면 바꿀 수 없다.
- 남의 세이브는 `publicView` 말고는 절대 내려가지 않는다. `visit`는 세이브를 쓰지 않는다.
- 커밋 `type: 내용` + 세션 attribution 두 줄.

## Review Focus

1. 섬을 안 고른 사람이 배 창에서 "내 섬"을 누르면 출발 전에 고르는 창이 뜨고, 창을 닫으면 출발하지 않는다(모양 없이 섬에 도착하는 경우가 없다). 고르기 요청이 실패해도 출발하지 않는다 → Task 5 테스트.
2. 친구 섬에 있는 동안 친구가 아이디를 바꾸거나 승인이 풀려도 화면이 죽지 않는다(이미 받은 view로 계속 그린다, 다시 오면 `visit` 실패 안내) → Task 5.
3. 남의 섬에서 새로고침하면 마을 시작 위치(남의 섬 위치는 저장 안 함) → Task 4·5.
4. `visit`로 자기 자신을 고르거나, 세이브가 없는 사람·숨김 게임 → 각각 정해진 오류(`self`, `no_save`, 404) → Task 1.
5. 장소 키가 48자 규칙을 넘지 않고, 주인 id 대문자·하이픈이 섞여도 같은 키 → Task 3.

### Task 1: 플랫폼 — visit, world_players, 장소 키 규칙

**Files:** `src/games/types.ts`(WorldLogic `publicView?`), `supabase/functions/world/handler.ts` + `handler.test.ts`, `src/lib/api.ts`(`worldVisit`), `src/platform/world/presence.ts`·`room.ts`(장소 규칙) + 테스트, `supabase/migrations/<ts>_world_players.sql`, `supabase/tests/24_world_players.test.sql`, `src/test-fixtures/world.ts`(테스트 게임에 publicView)

**Interfaces (Produces):**
- `WorldLogic.publicView?(state: State): unknown`
- handler: `{ game, action: 'visit', owner: string }` → 200 `{ owner: { id, handle }, view }`. 주인 id 형식이 uuid가 아니면 400 `bad_owner`; 본인이면 400 `self`; 주인이 없거나 승인 아님 404 `no_owner`; 세이브 없음 404 `no_save`; 게임에 publicView 없음 400 `no_public_view`; 세이브가 코드보다 새 버전 409 `version_newer`. 트랜잭션·잠금 없이 읽고, migrate만 하고 쓰지 않는다. 숨김 게임 규칙은 load/act와 같다.

### Task 3: 섬 모듈·맵 2종·텐트

**Files:** Create `src/games/fishing/isle.ts`(+test), `maps/isle-crescent.ts`, `maps/isle-twin.ts`; Modify `maps/index.ts`, `map.ts`(`MapOpts.buildingSprite`), `scene.ts`, `sprites.ts`(텐트), 맵 테스트

**Interfaces (Produces):**
- `isleMap(layout: IsleLayoutId): MapDef`, `isleArrival(layout: IsleLayoutId): TileFacing`(배에서 내리는 칸, 선착장 front 옆 육지)
- `mapFor(area: AreaId, layout?: IsleLayoutId | null): MapDef | null` — `isle`이면 layout이 있을 때만 그 맵, 없으면 null. 다른 지역은 layout 무시.

- `placeName(key: string, opts: { selfId: string | null; players: readonly { id: string; handle: string }[] }): string | null` — 지역이면 `AREAS` 이름, 섬이면 내 섬/"{아이디}의 섬"/"누군가의 섬", 모르면 null.
- `MapDef.buildingSprite: string`(기본 `'hall-exterior'`), 섬은 `'tent'`(직접 그린 32×32 안팎 텐트).
- 두 섬 맵: 48×36, `indoor: false`, `onWorldMap: false`, `spots: {}`, 남쪽 선착장 하나 `{ target: 'village', entry: { tx: 42, ty: 28, facing: 'up' } }`(낚시 섬의 마을행 도착과 같은 칸), 텐트 건물(B/D, 문은 걸을 수 있지만 출구 없음), 텐트 문 앞 고정물 notice `'텐트 안은 아직 들어갈 수 없어요'`, 섬 안쪽은 나무·바위로 막힘. 텐트 앞·선착장·바닷가가 서로 닿는다.
