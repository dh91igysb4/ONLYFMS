# 펨타듀 낚시 — 가방 물고기 잠금 (짧은 설계)

## 왜
판매는 `sell` 하나뿐이고 가방을 통째로 비운다. 전설은 한 번 잡으면 다시 나오지 않아서, 지금은 전설을 가방에 남겨 둘 방법이 없다. 사용자는 전설을 가방에 보관하고 싶어 한다.

## 목표·비목표
- 목표: 가방에서 물고기를 잠그면 "전부 팔기"에서 빠진다. 잠금은 세이브에 남는다.
- 비목표: 낱개 판매, 별도 보관함(수조), 잠긴 물고기의 칸 면제. 잠긴 물고기도 가방 칸을 차지한다.
- 실패로 보는 것: 잠근 물고기가 어떤 경로로든 팔리는 것, 기존 세이브의 골드·가방·도감이 바뀌는 것.

## 방식
- 고른 방식: 가방 물고기에 `locked?: true`를 두고 서버 행동 `lock { index, locked }`로만 바꾼다. 서버 권위(세이브는 서버가 쥔다) 원칙 그대로.
- 버린 방식: (1) 화면에서만 잠금 기억 — 기기마다 다르고 서버 `sell`이 모르니 팔린다. (2) 낱개 판매 — 요청은 "일괄 판매에서 빼기"이고, 12~40칸을 하나씩 파는 건 수고만 늘린다. (3) 별도 보관함 — 가방 칸을 안 먹어 좋지만 범위가 크다. 필요하면 나중에.

## 설계
- `Fish`에 `locked?: true` (잠기지 않았으면 필드 없음 — 기존 세이브·테스트의 물고기 모양 그대로).
- `lock { index, locked }`: `index`가 가방 범위의 정수, `locked`가 boolean이 아니면 `bad_action`. 낚시 중에도 가능(추첨·판정과 무관).
- `sell`: 잠기지 않은 물고기만 팔고 잠긴 물고기는 순서 그대로 남긴다. 팔 물고기가 없으면 `bag_empty`.
- 사용자 승인 사항(Claude 제안): 전설은 잡는 순간 자동 잠금. 이미 가방에 있는 전설도 `migrate`에서 잠근다(v4 이하 세이브만 — v5 세이브에서 직접 푼 잠금은 유지). 해제는 직접 가능.
- 화면: 가방 칸이 버튼이 되어 누르면 잠금/해제, 잠긴 칸에 자물쇠 표시. 상점 문구 "팔 물고기 n마리 · 잠금 m마리 · 예상 G", 예상 금액은 잠기지 않은 것만.
- `logic.version` 5, `world` 함수 재배포. 찌 계획도 5를 쓰므로 나중에 머지되는 쪽이 6으로 올린다.

## 빌더 재량
자물쇠 표시 모양(theme 토큰 색), 문구 세부.
