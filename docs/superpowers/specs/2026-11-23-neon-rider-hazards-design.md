# 네온 라이더 위험물(닿으면 죽는 장애물) 설계 — 움직이는 장애물 1단계

작성: 2026-11-23. 본 설계 `2026-11-23-neon-rider-design.md`(이하 "본 설계")에 더하는 문서다. 사용자와 대화로 정한 것과 내가 정한 것("내 판단")을 구분해 적는다.

## 1. 의도

영상(예전 버전)과 나무위키(최신 버전)에 나오는 빨간 장애물을 넣는다. 지금 게임에는 "닿으면 죽는 지형"이 없어서 영상의 빨간 톱니, 도는 빨간 호, 가시 바닥을 못 만들었고, 가시는 바닥 없는 틈으로 대신하고 있다. 사용자의 기준은 계속 "영상·원작과 최대한 비슷하게"다.

움직이는 장애물은 3단계로 나눴다(사용자 승인).
- **1단계(이 문서):** 닿으면 죽는 것. 위치가 시간만으로 정해지고, 차는 닿았는지만 본다.
- 2단계(별도 설계): 올라타는 움직이는 길(스위치 도로, 일회성 도로, 원숭이 꼬리, 오메가 점프, 노란 초승달, 초록 고리).
- 3단계(별도 설계): 밀리는 물체(넘어지는 블록).

## 2. 목표·비목표·실패 조건

**목표**
- 아래 위험물 종류를 시뮬·화면에 넣고, 영상·위키에 나온 자리에 템플릿으로 배치한다.
  - 빨간 톱니(제자리, 또는 왕복)
  - 도는 빨간 날(배럴형 바퀴, 팩맨 원반, 환풍기, 원형 배럴, 루프 안 빨간 호)
  - 길쭉한 창(일정 간격으로 땅에서 튀어 오름)
  - 가시 바닥·가시 띠(지금의 바닥 없는 틈을 대신)
  - 레이저(가는 빨간 선)
- 고정 지형 두 종(위키의 굽은 길, 스마일)을 같이 넣는다.

**비목표**
- 올라타는 움직이는 길, 밀리는 물체(2·3단계)
- 봇 통과 검증. 사용자 결정으로 계속 꺼 둔다. 사용자가 플레이하며 고친다.
- 효과음

**실패 조건**
- 같은 시드와 같은 입력에서 결과가 달라진다(결정성 깨짐).
- 화면에 보이는 위험물과 판정이 어긋난다(닿지 않았는데 죽거나, 겹쳤는데 산다). 허용 오차는 아래 §5.4.
- 위험물이 차와 무관한 이유로 움직이거나, 차 상태에 따라 움직임이 바뀐다(1단계 위험물의 움직임은 시간만의 함수).
- 원작의 그림을 그대로 쓴다.

## 3. 만드는 방법 (세 가지 중 1번, 사용자에게 알림)

| 방법 | 내용 | 판단 |
|---|---|---|
| **1. 템플릿 안에 위험물을 적는다 (선택)** | 템플릿의 길 선분과 함께 위험물(모양 + 움직임)을 적는다. 위치는 틱 수만의 정수 함수. 매 이동 단계마다 바퀴 둘·차체 판정원과 겹치는지 보고 겹치면 죽는다 | 결정성이 그대로고, 영상처럼 장애물마다 정해진 자리에 놓인다 |
| 2. 위험물을 코스와 따로 무작위 배치 | 템플릿과 무관하게 뿌린다 | "틈 위에 뜬 톱니" 같은 영상의 배치가 안 나온다 |
| 3. 길 선분에 "죽는 선분" 표시 | 정적 선분만 | 회전·왕복·창이 안 된다 |

## 4. 위험물 모델

### 4.1 모양 세 가지 (내 판단)

모든 길이는 u(1/16 mm), 각도는 TURN(4096 = 한 바퀴), 시간은 틱. 정수만 쓴다.

1. **원 `disc`**: 중심 (x, y), 반지름 r. 빨간 톱니, 팩맨 원반의 몸통.
2. **도는 날 `blades`**: 중심 (x, y)에서 안쪽 반지름 rIn ~ 바깥 반지름 rOut 사이의 부채꼴 고리 조각 n개. 조각 하나의 폭은 w(TURN), 조각은 같은 간격으로 놓인다. 시작각 a0, 각속도 ω(TURN/틱, 음수면 시계 방향).
   - 배럴형 바퀴: rIn = 0, n = 2, 마주 보는 두 부채꼴.
   - 환풍기: rIn = 0, n = 3~4.
   - 원형 배럴, 루프 안 빨간 호: rIn이 rOut 가까이(두께 0.3~0.5 m), n = 2~3.
   - 팩맨: n = 1, w = 3/4바퀴.
3. **막대 `bar`**: 두 끝점 (x0, y0)–(x1, y1)과 반지름 r의 캡슐. 가시 띠·가시 바닥(낮고 긴 막대, 화면에는 톱니 줄로 그림), 레이저(가는 막대), 창(세로 막대).

### 4.2 움직임 (모두 틱 수만의 함수)

- `none`: 고정. 톱니는 화면에서만 돌아가 보인다(판정은 원이라 무관).
- `rotate`(blades 전용): 각도 = a0 + ω × t.
- `swing`(disc·bar): 기준 위치에서 벡터 (ax, ay)만큼 삼각파로 왕복. 주기 P틱, 위상 φ틱. 위치 = 기준 + (ax, ay) × tri(t), tri는 0 → 1 → 0을 오가는 정수 삼각파(분자/분모로 계산).
- `pop`(bar 전용, 창): 주기 P틱마다 숨음 → 솟음 → 서 있음 → 내려감. 숨어 있을 때는 판정 없음. 솟는 높이는 막대 위쪽 끝을 선형으로 움직여 표현한다. 단계 길이(틱)는 템플릿에 적는다.

t는 그 판의 `tick`이다(판정 시각은 §5.2). 같은 시드에서도 도착 시점에 따라 만나는 위상이 달라진다. 이게 원작의 "타이밍" 요소다.

### 4.3 템플릿 표기

`pieces.ts`의 `Prim`에 `{ t: 'hazard'; h: HazardDef }`를 더한다. 보석처럼 현재 펜 위치를 기준으로 놓고, 펜은 움직이지 않는다. 앞뒤 평지 자르기(`trimFlats`)를 할 때는 보석과 같이 x를 옮긴다.

`Built`에 `hazards: HazardDef[]`(템플릿 좌표)를 더하고, 코스가 월드 좌표로 옮겨 번호를 붙인다.

### 4.4 코스

`Course`에 `hazardsNear(box): readonly Hazard[]`를 더한다. 차의 판정 상자와 위험물의 "움직임 전체를 덮는 상자"가 겹치는 위험물을 돌려준다. 공중에 오래 떠 있어도 놓치지 않도록, 진행 번호가 아니라 x 범위로 찾는다. 상자의 오른쪽 끝(box.x1)까지 구간이 아직 안 만들어졌으면 만들어 가며 찾는다(`seg(i)`가 그러듯이). 위험물은 구간이 소유하고(구간을 만들 때 월드 좌표로 옮겨 번호를 붙인다), 찾을 때는 x로 구간을 이진 탐색한다(내 판단).

## 5. 판정

### 5.1 언제
틱 안의 이동 단계(SUBSTEPS)마다 막대 제약·충돌을 푼 뒤 확인한다. 지금 차체 판정원을 확인하는 자리와 같다. 판정 대상은 뒷바퀴(WHEEL_R), 앞바퀴(WHEEL_R), 차체 판정원(HEAD_R) 세 원이다.

### 5.2 위험물 시각
빠르게 도는 날을 놓치지 않도록, 이동 단계 k(0부터)에서는 시각을 `t + (k+1)/SUBSTEPS` 틱으로 본다. 그 이동 단계가 끝난 바퀴 위치와 같은 시각이고, 마지막 단계는 틱 끝(t + 1)이다. 정수로는 "부분 틱" 단위 T = t × SUBSTEPS + k + 1을 쓰고, 각속도·주기는 틱 단위로 적은 값을 부분 틱으로 환산한다(내 판단). 이동 단계 사이에 날 끝이 원 반지름보다 많이 움직이면 놓칠 수 있다. 그래서 템플릿을 만들 때 날 끝 속도 ω × rOut × 2π / TURN / SUBSTEPS를 바퀴 반지름(WHEEL_R = 2880 u) 아래로 둔다. 이 조건을 테스트로 고정한다.

### 5.3 겹침 계산 (정수)
- 원–원: 중심 거리² < (r1 + r2)².
- 원–캡슐: 원 중심에서 선분까지 거리 < r + 막대 반지름. 기존 `hitsCircle`과 같은 계산이다.
- 원–부채꼴 고리: 원 중심의 극좌표 (ρ, φ)를 `isqrt`·`atan2T`로 구한다.
  - ρ가 [rIn − c, rOut + c] 밖이면 안 겹친다(c = 원 반지름).
  - φ가 조각의 각도 범위 안이면 겹친다.
  - 범위 밖이면, 조각의 두 곧은 변(선분)과 두 끝 모서리까지의 거리로 판정한다.
  - 정확한 정수 계산이 어려운 부분은 조각을 선분 여러 개로 근사해도 된다. 오차는 §5.4 안이어야 한다.

### 5.4 허용 오차
화면에 보이는 모양과 판정의 차이는 바퀴 반지름의 1/4(45 mm) 이내. 테스트로 대표 경우를 고정한다(원 가장자리, 부채꼴 끝, 막대 끝).

### 5.5 결과
겹치면 `dead = 'crash'`로 끝낸다. 차체 박살과 같은 사망 화면이다(내 판단: 새 사망 사유를 만들지 않는다). 지급 대기 중(`pending`)이거나 공중인 공중제비는 지급하지 않고, 앞선 틱에 이미 지급된 점수와 `lastAward`는 그대로 남는다(기존 규칙 그대로).

## 6. 화면

- 위험물은 빨간 네온(`#ff3355` 계열, 캔버스 내부 색 예외 안)으로 그린다. 길처럼 넓고 옅은 선 위에 밝은 선을 겹치고, `shadowBlur`는 쓰지 않는다.
- 톱니는 톱니 가장자리 원으로 그리고, 화면에서만 천천히 돈다.
- 날은 채운 부채꼴, 고리 조각은 두꺼운 호, 창은 뾰족한 세로 막대, 가시 띠는 삼각형 줄, 레이저는 밝은 가는 선으로 그린다.
- 그리는 시각은 보간 시각(prev 틱 + alpha)이다. 판정 시각과 1틱 안에서 다를 수 있다(허용).
- 위치·각도 계산은 시뮬과 같은 함수를 쓴다(화면용 별도 공식 금지).

## 8. 테스트

봇 통과 검증은 계속 끈다. 대신 다음을 테스트로 고정한다.
- 움직임 함수: 정수 결과, 주기성, `swing`의 끝점, `pop`의 단계 경계, 같은 t → 같은 위치.
- 겹침: 원–원, 원–캡슐, 원–부채꼴 고리의 경계 사례(§5.4 오차 안). 회전한 날의 각도 경계 포함.
- 시뮬
  - 톱니로 달려가면 `crash`.
  - 원형 배럴은 틈이 맞는 시각에 밑으로 지나가면 산다(시작 틱을 바꿔 두 경우 모두).
  - 창이 숨은 시각에 지나가면 살고, 솟은 시각이면 죽는다.
  - 결정성(같은 입력 → 같은 상태), 상태 크기 한도 그대로.
- 빠른 날 조건(§5.2)을 모든 템플릿의 blades에 대해 확인.
- 코스: `hazardsNear`가 공중 비행 중에도 겹치는 위험물을 돌려준다. `trimFlats` 뒤 위험물 위치가 보석과 같이 옮겨진다.
- 렌더: 위험물을 그릴 때 `shadowBlur` 없음, 빨간색 사용, 보이는 위험물만 그림.
- 기존 테스트 유지. `spikepit`·`spikefloor` 모양이 바뀌므로 관련 기대값(`fall` 관련 포함)은 다시 계산한다.
- 봇 기반 테스트(`balance.test.ts`, `gate/*.gate.test.ts`)는 지금처럼 `describe.skip`으로 둔다. 다시 켤 때는 위험물 템플릿의 도착 시각(위상)을 다루는 방법을 따로 정해야 한다(그때의 일).
