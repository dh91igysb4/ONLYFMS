# 몰래 수능 (`sneak-exam`) 설계

작성: 2026-11-22. 플랫폼 설계(`2026-10-31-onlyfms-platform-design.md`)와 볼 런 설계(`2026-11-07-ball-run-design.md`)의 구조를 따른다. 1장과 2장의 접근 선택은 사용자와 대화로 확정했고, 3장부터는 사용자가 위임해 이 문서에서 정했다("내 결정" 표시).

## 1. 의도와 범위

- **무엇**: 수능 시험장에서 감독관에게 들키지 않고 커닝 도구로 답을 알아내 답안지를 채우는 1인용 잠입 게임. 친구들과 최고 점수를 겨룬다.
- **참고**: itch.io의 커닝 게임 녹화(56초)를 분위기·구조의 레퍼런스로만 삼는다. 똑같이 만들지 않는다. 이름·문구·문제·모델·수치는 모두 새로 만든다(원작의 텍스트·에셋을 가져오지 않는다).
- **목표**
  - 감독관이 걸어오는 것을 보고 도구를 켜고 끄는 타이밍 싸움이 재미의 중심이다.
  - 한 판 2분 이내, 모바일 세로 화면에서 버튼만으로 조작한다.
  - 판마다 감독관 성향과 순찰이 달라 외워서 깰 수 없다.
- **범위 밖(non-goals)**: 데일리·대회·대전, 서버 재검증, 효과음, 시점 회전, 감독관 여러 명, 난이도 옵션, 도구 외 술법(답안지 바꿔치기 등), 튜토리얼 전용 모드(첫 화면 안내문으로 대신한다).
- **이러면 실패(anti-goals)**: 감독관이 안 보이는 곳에서 이유 없이 적발되는 것, 찍기만 해도 상위 점수가 나오는 것, 가만히 기다리는 게 최선인 것.
- **자유 플레이 전용.** `freeStats: 'score'`, 최고 점수 리더보드. 신뢰 모델은 볼 런·양치와 같다(클라이언트 점수, 시드·행동 기록은 재현·분석용).
- 처음에는 `hidden: true`로 머지하고 관리자 확인 뒤 공개한다.

## 2. 접근

| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 고정 1인칭 3D (선택)** | 내 자리에서 교실을 보는 고정 카메라, 박스 로우폴리, 조작은 버튼 | 감독관이 다가오는 압박감을 가장 싸게 살린다. 볼 런의 Three.js 구조(동적 import, 고정 틱 루프, 묶음 전송)를 재사용한다. 2D보다 작업량이 많다 |
| B. 2D 탑다운 | 캔버스로 교실을 내려다보고 시야를 부채꼴로 표시 | 가장 빠르고 규칙이 잘 읽히지만 퍼즐에 가까워져 긴장이 약하다 |
| C. 자유 시점 3D | 고개를 돌려 옆자리를 훔쳐보는 조작까지 | 모바일 조작이 어렵고 작업량이 A의 두 배 이상. A 이후 확장 후보 |

사용자가 A를 골랐다.

## 3. 규칙 (내 결정)

### 3.1 한 판

- 5지선다 8문제, 제한 시간 120초(7200틱, 60Hz). 가장 안전한 도구만으로는 방해 없이 풀어도 80초가 걸려, 위험한 도구를 섞어야 시간이 남는다.
- 문제는 풀 수 없는 농담 문제다(§5). 답을 알려면 커닝 도구를 켜야 한다. 모르는 채 찍어도 된다(정답 확률 1/5).
- 끝나는 경우: `submit`(제출 버튼), `timeout`(시간 종료), `caught`(의심도 100%), `give_up`.

### 3.2 교실 좌표

단위 mm, 정수. x는 좌우, z는 뒷벽에서 칠판 쪽으로.

- 책상 4열 × 5줄. 열 중심 x = −2700, −900, 900, 2700. 줄 중심 z = 1000(맨 뒷줄, 0번 줄), 2400, 3800, 5200, 6600.
- 통로 5개: x = −3600, −1800, 0, 1800, 3600. 앞 통로 z = 8200. 교탁 (0, 8800).
- **내 자리: (900, 1000)** — 오른쪽에서 둘째 열, 맨 뒷줄. 뒤에는 통로가 없어 감독관은 늘 앞이나 옆에 있다.
- 감독관은 앞 통로와 세로 통로 위에서만 움직인다. 세로 통로에서는 줄 중심 z 다섯 곳 중 하나까지 내려온다.

### 3.3 거리와 시선

감독관에서 내 자리까지의 벡터 p, 제곱 거리 d².

- 구역: `near` d² ≤ 1500², `mid` d² ≤ 3500², 그 밖은 `far`. (통로 x=0 또는 1800의 0번 줄 = 900mm → near. 같은 통로 1번 줄 = 약 1664mm → mid.)
- 감독관의 시선 f는 네 방향 중 하나다. **본다(seen)** = 졸고 있지 않고, `along = f·p > 0`이며 `|f×p| ≤ 2·along`(정면에서 약 63° 안). 걸을 때 시선은 진행 방향이다.
- 다른 학생·책상에 가려지는 것은 계산하지 않는다.

### 3.4 도구

한 번에 하나만 켠다. 켜는 것은 즉시, 끄는 데는 숨기는 시간이 걸리고 그동안 풀이는 멈추지만 노출은 계속된다. 다른 도구로 바꾸려면 끄고(숨기는 시간) 켠다.

| 도구 | 한 문제 풀이 | 숨기는 시간 | 틱당 의심도 증가 (본다 near / 본다 mid / 본다 far / 안 봄 near / 안 봄 mid) |
|---|---|---|---|
| 스마트 안경 | 10초 (6/틱) | 0 | 60 / 10 / 0 / 0 / 0 |
| 무선 이어폰 | 5초 (12/틱) | 20틱 | 120 / 20 / 0 / 120 / 20 (소리라 시선 무관) |
| 휴대폰 | 2초 (30/틱) | 40틱 | 250 / 80 / 40 / 40 / 0 |

- 풀이 진행도는 문제마다 0~3600. 도구가 켜져 있고(숨기는 중 아님) 선택한 문제가 아직 안 풀렸으면 틱마다 도구 속도만큼 오른다. 3600이 되면 그 문제의 정답이 공개된다. 진행도는 도구를 꺼도, 문제를 바꿔도 남는다.
- 정답이 공개돼도 도구는 켜진 채다. 직접 끄거나 다음 문제로 넘겨야 한다.
- 감독관이 조는 동안에는 모든 증가가 0이다.

### 3.5 의심도

- 0~10000 정수. 틱마다 위 표의 값을 더한다. 그 틱의 증가가 0이면 5만큼 줄어든다(100% → 0%에 약 33초).
- 10000에 닿으면 `caught`. 적발 문구는 켜져 있던 도구에 따라 다르다.
- 6000 이상이면 감독관의 다음 행선지가 내 옆 통로(x=0 또는 1800, 0번 줄)로 고정된다(§3.6 "주시").

### 3.6 감독관

판마다 시드로 세 성향 중 하나가 정해지고, 시작 화면에 "오늘의 감독관"으로 알려 준다.

| 성향 | 걷는 속도 | 특징 |
|---|---|---|
| 순찰형 | 25mm/틱 | 거의 쉬지 않고 통로를 돈다. 멈춰 보는 시간이 짧다 |
| 매의 눈 | 20mm/틱 | 주로 앞에 서 있지만 `far`에서 보는 값이 2배이고 안경도 `far`에서 잡는다(5/틱). 교탁에서 반 전체를 오래 본다 |
| 졸음형 | 15mm/틱 | 교탁에서 자주 존다(60~240틱). 깨는 시점은 예고 없다. 가끔만 순찰한다 |

상태 기계(성향별 가중치·시간 범위는 `constants.ts`):

- `front`: 앞 통로에 서서 반을 본다(시선 −z) 또는 존다.
- `walk`: 그래프 위에서 목적지까지 이동. 앞 통로를 따라 가로로, 세로 통로를 따라 세로로만.
- `look`: 세로 통로의 줄 위치에 멈춰 왼쪽이나 오른쪽을 본다(시드로 결정, 주시 중이면 내 쪽). 통로 x=0 또는 1800의 0번 줄에서 보는 `look`은 주시 여부와 관계없이 늘 나를 향한다.
- 순찰형은 `look`이 끝나면 1/3 확률로 같은 통로의 다른 줄로 가서 한 번 더 본다(재확인, `relooked`로 한 번만). 다른 성향은 하지 않는다(`relookOf`).
- 시작 직후 120틱(`START_GRACE`)은 감독관이 교탁 앞(x=0)에 서서 반을 본다. 이 동안은 움직이지 않는다.
- 결정 시점(`front`·`look`의 대기 종료)마다 다음 행동을 뽑는다. 주시 조건이면 내 옆 통로 0번 줄로 간다.
- 난수는 시뮬 상태에 담긴 32비트 정수 상태 하나를 `Math.imul`로 굴린다. 판의 모든 무작위(문제·정답·성향·순찰)는 시드에서 나온다.

### 3.7 점수

- `정답 수 × (100 + 시간 보너스)`. 시간 보너스 = `floor(남은 틱 × 100 / 7200)`, `submit`으로 끝났을 때만 붙는다.
- `caught` = 0점. `timeout`·`give_up`·진행 중 = `정답 수 × 100`.
- 상한 1600(8 × 200). `scoreMax: 1600`, `scoreDecimals: 0`.
- 기대 점수 비교: 전부 찍고 바로 제출 약 320점, 안경만으로 80초에 다 풀면 1064점, 휴대폰을 섞어 25초에 다 풀면 약 1430점. 찍기도 안전 일변도도 최선이 아니다.
- `actionCount` = 틱.

## 4. 구조

### 4.1 파일 (`src/games/sneak-exam/`)

| 파일 | 역할 |
|---|---|
| `manifest.ts` | 매니페스트 |
| `constants.ts` | 틱·좌표·도구 표·의심도·성향 수치 |
| `rng.ts` | 정수 난수(`nextRng`, `rngInt`, `seedInt`). 시뮬·시험 구성의 난수는 이 모듈만 쓴다 |
| `questions.ts` | 문제 은행(문구만) |
| `exam.ts` | `getExam(seed)`: 시드에서 문제 8개·정답·감독관 성향·감독관 난수 초기값을 계산(최근 8개 캐시) |
| `proctor.ts` | 감독관 상태 기계 한 틱 |
| `sim.ts` | `initSim(exam)`, `step(state, exam)`(한 틱), 명령 `parseCmd`·`canApply`·`applyCmd`, 시선 `sees`, 구역 `zoneOf` |
| `logic.ts` | `GameLogic` 래퍼, 행동 검증 |
| `bots.ts` | 밸런스 테스트용 봇 |
| `render/view.ts` | 화면 계산(순수, three 없음): 카메라 값 `CAM`, 시야 밖 판정 `offscreenSide` |
| `render/scene.ts` | Three.js 교실·감독관·책상 위 답안지 |
| `Game.tsx`, `sneak-exam.css` | 캔버스, HUD, 버튼, 고정 틱 루프 |

`render/`와 `Game.tsx`, `*.css`를 뺀 파일은 순수 TS, 외부 의존 없음, 상대 import에 `.ts` 명시. 시뮬 상태는 모두 정수이고 삼각함수·`sqrt`를 쓰지 않는다(볼 런 §3.1과 같은 결정성 규칙).

### 4.2 상태와 행동

```ts
type SimState = {
  tick: number
  rng: number                                  // 감독관 난수 상태
  proctor: { x: number; z: number; face: 0|1|2|3; mode: 'front'|'walk'|'look'; dozing: boolean; timer: number; tx: number; tz: number; relooked: boolean }
  susp: number
  tool: 0|1|2|3                                // 0 = 없음
  stow: number                                 // 남은 숨기는 틱
  q: number                                    // 선택한 문제
  prog: number[]                               // 8개, 0~3600
  marks: number[]                              // 8개, −1 또는 0~4
  end: null | 'submit' | 'timeout' | 'caught' | 'give_up'
}
```

- 퍼즐은 `{ seed }`(볼 런과 같은 32자리 16진수). 문제 8개·정답·성향은 `getExam(seed)`가 시드에서 계산한다. 시뮬은 `initSim(exam)`·`step(state, exam)`처럼 exam을 받는다.
- 행동 `{ type: 's', n, c? }`: n틱(정수 0~120) 진행한 뒤 명령 c를 적용한다. n틱 안에 판이 끝나면 c는 버린다(적용하지 않고 오류도 아님).
  - `['t', 0~3]` 도구 켜기/끄기, `['q', 0~7]` 문제 선택, `['m', 문제, −1~4]` 마킹(시간·의심도 비용 없음), `['x']` 제출.
  - 형식·범위 위반, 지금 적용할 수 없는 명령(`canApply` 거짓), 끝난 뒤 행동은 `{ error }`이고 상태는 그대로다.
- 화면은 명령이 있을 때 즉시, 없으면 30틱마다 `{ type: 's', n: 30 }`을 보낸다.
- `publicState`는 시뮬 상태에 "공개된 정답"(진행도 3600인 문제만)을 붙인 것. `reveal`은 정답 전체와 성향.
- 알려진 한계: 시드가 브라우저에 있어 코드를 읽으면 정답을 계산할 수 있다(볼 런·양치와 같은 신뢰 모델).

## 5. 문제 은행 (내 결정)

수능 문제 말투를 흉내 낸, 답을 알 수 없는 농담 문제 30개 이상. 실제 기출 문제나 레퍼런스 게임의 문구를 쓰지 않는다. 정답 번호는 문구와 무관하게 시드로 정한다. 말투 예:

- "출제 위원이 오늘 아침에 먹은 것으로 가장 적절한 것은?" ① 김밥 ② 시리얼 ③ 어제 남은 치킨 ④ 커피만 ⑤ 안 먹음
- "감독관이 지금 떠올리고 있는 숫자는?" ① 7 ② 12 ③ 38 ④ 0 ⑤ 숫자를 떠올리고 있지 않다
- "다음 중 이 문제의 정답은?" ① ①번 ② ②번 ③ ③번 ④ ④번 ⑤ ⑤번

문구만 고치는 변경은 `logic.version`을 올리지 않는다. 문제를 더하거나 빼면 올린다.

```
┌──────────────────────────┐
│ 의심도 ▓▓▓░░░░░░░   2:41 ⏸ │
│ ◀ 문제 3/8 ▶                │
│ 출제 위원이 오늘 아침에…      │
│ ① ② ③ ④ ⑤   (도구가 알려 준 답 강조) │
│                            │
│   [3D 교실: 앞자리 학생들,    │
│    칠판, 걸어 다니는 감독관]  │
│ ◀ 감독관                    │  ← 시야 밖일 때 가장자리 표시
│   [책상 위 답안지]           │
├──────────────────────────┤
│ [안경] [이어폰] [휴대폰]      │
│ ① ② ③ ④ ⑤ 마킹      [제출]  │
└──────────────────────────┘
```

- 카메라는 내 자리 눈높이(1150mm)에서 칠판 쪽 고정. 세로 시야각 75°, 아래로 12° 숙인다(책상 위 답안지가 화면 아래에 걸린다). 바로 앞자리는 비어 있어 학생은 18명이다. 모바일 세로 기준, 넓은 화면에서는 가운데 세로 상자.
- 교실·학생·감독관은 박스 조합 로우폴리. 감독관은 걷는 동안 다리가 흔들리고, 조는 동안 고개가 숙여진다. 시선 방향이 몸 방향으로 보여야 한다.
- 감독관이 카메라 시야 밖(옆 통로 0번 줄 등)이면 화면 가장자리에 방향 표시를 띄운다. 안 보이는 적발을 막는 장치다. 그 감독관이 지금 나를 보고 있으면(`sees`) 표시에 "보는 중"을 더하고 더 강한 색으로 바꾼다.
- 도구 표시: 안경은 화면 테두리 색, 이어폰은 귀 쪽 아이콘과 진행 표시, 휴대폰은 책상 아래 빛. 숨기는 중에는 버튼에 "숨기는 중"이라고 표시한다(남은 시간 숫자는 없다).
- 시작 전: 규칙 세 줄, 도구 표, "오늘의 감독관", 시작 버튼. 시작 전·일시정지·탭 숨김 중에는 틱이 멈춘다.
- 적발 연출: 감독관이 내 자리 앞으로 와 화면을 가린 뒤 결과. 결과에는 종료 사유, 정답 수, 시간 보너스, 문제별 정오.
- PC 키: 1·2·3 도구, ←/→ 문제, Q·W·E·R·T 마킹, Enter 제출, Space 일시정지. 입력 칸에서 친 키와 포커스된 버튼·링크의 Enter·Space는 게임 키로 쓰지 않는다.
- WebGL 실패·동적 import 실패·언마운트 정리는 볼 런 §6.3과 같다. 문구는 모두 한국어.
