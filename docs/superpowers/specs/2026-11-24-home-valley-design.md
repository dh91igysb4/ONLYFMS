# 메인 화면 개편 — 밸리 미리보기와 바로가기 버튼 (펨타듀 밸리 2단계)

- 날짜: 2026-11-24
- 상태: **승인됨** (2026-11-24)
- 관련: `2026-11-23-wallet-design.md`(1단계, 머지·배포됨), `2026-11-01-home-dashboard-design.md`(지금 홈, 이 문서가 대체), `2026-11-24-fishing-wardrobe-design.md` §7(프로필 캐릭터 등록 방식), `2026-11-24-fishing-map-design.md`

## 1. 의도

사이트의 목표가 "집과 캐릭터를 키우는 게임 하나(펨타듀 밸리)"로 바뀌었고, 1단계에서 낚시 골드가 사이트 공용 지갑이 됐다. 그런데 메인은 아직 정보 블록 6개로 된 대시보드라서 밸리가 사이트의 중심이라는 것이 화면에 드러나지 않는다. 이번 작업으로 메인을 사용자가 그린 세 칸 구조로 바꾼다.

```
┌──────────────────────────┐
│ 홈 게임 대회 대전 … 지갑 │  1  지금 그대로
├──────────────────────────┤
│                          │
│    펨타듀 밸리 미리보기   │  2  정사각형, 누르면 밸리로
│                          │
├──────────────────────────┤
│ [데일리 후알야 ●] [대전 2]│  3  이름만 있는 버튼 + 할 일 표시
│ [볼 런] [네온 라이더] …  │
└──────────────────────────┘
```

사용자 원문(요약): 1은 지금과 같게, 2에 펨타듀 밸리 세계가 보이게, 3에 각종 기능 버튼을 설명 없이 이름만 넣는다. 오픈월드 느낌이되 다른 게임·기능으로 가는 클릭 수는 지금과 같게 유지한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- `/`가 상단 내비게이션(그대로) + 밸리 미리보기 + 바로가기 버튼 묶음이 된다.
- 미리보기에는 내 캐릭터가 지금 옷차림으로 내가 마지막에 있던 자리에 서 있고, 게임 시계에 맞춰 낮밤·날씨가 바뀐다. 누르면 밸리(`/world/fishing`)로 들어간다.
- 버튼은 이름만 적고, 할 일이 있으면 점(●)이나 숫자를 붙인다.
- 어떤 게임·기능으로 가든 클릭 수가 지금보다 늘지 않는다.
- 플랫폼 코드에 게임 id 분기가 없다. 미리보기는 등록부로 찾는다.

**비목표**
- 메인에서 걷기·낚시 같은 조작 (사용자 선택: 미리보기만)
- 친구 캐릭터·집이 보이는 밸리 (3단계 집과 땅 이후)
- 순위·레이팅·기록을 메인에 표시하기 (리더보드·프로필에서 본다)
- 홈 블록 켜기·끄기·순서 바꾸기 (없앤다)
- 서버 함수·DB 스키마 변경 (§6의 열린 지역 기록은 기존 `game_records` 행 하나를 더하는 것뿐이다)

**실패 조건 (동작해도 실패)**
- 지금 1클릭으로 가던 곳(홈 블록의 데일리 버튼 등)이 2클릭이 된다.
- 메인을 열 때 `world` 함수를 부른다 (세이브 잠금 트랜잭션이 돌고 다른 탭의 낚시와 서로 기다리게 된다).
- 미리보기에 캐릭터가 걸을 수 없는 곳(물 위, 벽 안)에 서 있거나, 아직 안 연 지역에 서 있다.
- 폰에서 메인을 스크롤하려고 미리보기를 문질렀는데 스크롤이 안 된다.
- 미리보기가 계속 프레임을 그려 폰 배터리를 눈에 띄게 쓴다.
- 미리보기가 실패해서 버튼까지 안 보인다.
- 숨김 게임이 관리자가 아닌 사람에게 보인다.

## 3. 접근 방식

**2번 칸이 하는 일** (사용자 선택: 1)

| 3 | 밸리 지도 | 찍을 것이 내 위치뿐이라 집·땅이 생긴 뒤에야 의미가 있음 |

## 4. 화면 구성

### 4.1 배치
- **폰(기본)**: 세로 한 열. 미리보기는 화면 폭 전체의 정사각형, 그 아래 버튼 묶음.
- **넓은 화면(900px 이상, 기존 `.split` 기준점)**: 사용자 그림대로 세로 배치를 유지하되, 미리보기는 최대 480px 폭 정사각형으로 가운데 둔다. 버튼 묶음은 그 아래 같은 폭. (**내 판단**: 그림이 세로이고, 좌우로 나누면 "밸리가 위에 있다"는 인상이 약해진다. 넓은 화면에서 남는 여백은 감수한다.)
- 제목 줄(`홈`, `편집` 버튼)은 없앤다.

### 4.2 버튼 묶음
- 2열 격자(넓은 화면은 3열). 버튼 안에는 이름 한 줄과 오른쪽 끝에 할 일 표시만. 설명 문구 없음.
- 순서(**내 판단**: 매일 할 일이 위로):
  1. 데일리가 있는 게임마다 `데일리 <게임 이름>` → `/play/<id>/daily`. 오늘 아직 안 끝냈으면 `●`.
  2. `대전` → `/duel`. 진행 중인 내 대국 수(0이면 표시 없음). `duel_list()`에 내 차례 정보(`due`)가 있으면 그 수를 쓰고, 없으면 진행 중 수.
  3. `대회` → `/contests`. 진행 중이거나 24시간 안에 시작하는, 내가 참가한 대회 수.
  4. 자유 플레이가 있는 게임마다 게임 이름 → `/play/<id>/free`. 표시 없음.
- 지속형 게임(낚시)은 버튼을 따로 두지 않는다. 미리보기를 누르면 들어간다. 미리보기를 못 그리는 경우(§5.4)에는 같은 자리에 `<게임 이름> 들어가기` 버튼을 그린다.
- 목록은 등록부(`games`, `worlds`)에서 만든다. `manifest.hidden`이면 관리자에게만 보인다. 플랫폼에 게임 id 분기 없음.
- 할 일 표시는 버튼마다 따로 불러오고, 불러오는 중·실패면 표시만 없이 버튼은 그대로 보인다.
- 접근성: 표시가 있으면 버튼의 접근 이름에 덧붙인다(예: `데일리 후알야, 아직 안 풀었어요`, `대전, 진행 중 2개`).

### 4.3 클릭 수 비교
| 가는 곳 | 지금 | 바뀐 뒤 |
|---|---|---|
| 데일리 후알야 | 홈 블록 버튼 1클릭 | 1클릭 |
| 자유 플레이 게임 | 게임 탭 → 카드 버튼 2클릭 | 1클릭 |
| 낚시 | 게임 탭 → 들어가기 2클릭 | 미리보기 1클릭 |
| 내 대국 하나 | 홈 블록의 대국 링크 1클릭 | 대전 → 대국 2클릭 |
| 대회 하나 | 홈 블록의 대회 링크 1클릭 | 대회 → 대회 2클릭 |

마지막 두 줄은 늘어난다. 실패 조건을 지키려면 둘 중 하나가 필요하다:
- **(제안)** 진행 중인 내 대국·대회가 **딱 하나**면 `대전`·`대회` 버튼이 목록이 아니라 그 대국·대회로 바로 간다. 둘 이상이면 목록으로 간다. 지금 홈도 둘 이상이면 블록에서 하나를 골라 누르므로 1클릭은 그대로다.
- 이 규칙을 §11에서 사용자 확인 항목으로 둔다.

## 5. 밸리 미리보기

### 5.1 등록 (플랫폼, 게임 분기 없음)
- `Manifest.preview?: true`: 이 지속형 게임은 메인 미리보기를 그린다. 지금은 낚시만.
- 화면 등록: `src/games/ui.ts`의 `getWorldPreview(id)` → `ComponentType<WorldPreviewProps>`.
  ```ts
  type WorldPreviewProps = {
    userId: string
    records: { key: string; detail: string | null }[]   // user_records에서 이 게임의 행
    size: number                                        // 정사각형 한 변(CSS px)
  }
  ```
- 메인은 `worlds`에서 `manifest.preview`가 있고 화면이 등록된 첫 게임을 고른다(숨김이면 관리자만). 둘 이상이 되면 그때 정한다.
- 등록부 테스트: `preview` manifest ⇔ `getWorldPreview` 둘이 같이 있다.
- 메인은 `user_records(내 아이디)`를 한 번 불러 해당 게임 행을 넘긴다. 이미 프로필이 쓰는 RPC다.

### 5.2 낚시 미리보기가 쓰는 값
| 값 | 출처 | 없을 때 |
|---|---|---|
| 지역·위치·방향 | `loadPosition(userId)` (브라우저 저장) | 마을 시작 위치, 아래를 봄 |
| 옷차림 | `avatar` 기록(`detail` = 옷차림 JSON) | 기본 옷차림 |
| 열린 지역 | `areas` 기록(§6) | 기본 지역만 열린 것으로 |
| 순간이동기 불빛 | 그리지 않음(꺼진 그림) | — |
| 시각·계절·날씨 | `conditionsAt(서버 시각)` (`clock.ts`, `lib/serverTime.ts`) | — |
| 물때·얼음 | 기존 계산(`MapDynamic`)을 시각으로 | 정적 상태 |

- 저장된 지역이 열린 지역에 없거나 그 자리에 설 수 없으면 마을 시작 위치(기존 `startPosition` 규칙과 같게).
- 장면은 기존 `drawWorld`를 `phase: 'idle'`, `bobber/bar: null`, `fade: 0`, `hudTop: 0`으로 부른다. HUD 시계는 그대로 그린다(낮밤과 함께 "살아 있음"을 보여 줌).
- 정사각형에 맞춘 카메라: 캐릭터를 가운데 두고 맵 끝에서 멈추는 기존 카메라 계산을 정사각형 크기로 쓴다. 배율은 정수(지금 낚시 캔버스 규칙).

### 5.3 움직임과 성능
- 캐릭터는 대기 자세. 걷지 않는다.
- 다시 그리는 때: **게임 시각이 10분 바뀔 때(실제 10초)**, 그리고 비·눈이 오는 동안은 효과를 위해 초당 약 10프레임. 맑은 날은 10초에 한 번만 그린다.
- 탭이 안 보이면(`document.hidden`) 멈춘다. 화면 밖으로 스크롤돼도 멈춘다(`IntersectionObserver`).
- 맵 정적 캐시는 그 지역 하나만. 메인을 떠나면 놓는다(기존 `releaseSceneCache`).
- 낚시 그림 코드는 메인 첫 화면에 필요하므로 정적 import로 둔다(지금도 `ui.ts`가 낚시 화면을 정적 import한다). 번들 크기 변화를 PR에 적는다.

### 5.4 입력과 실패
- 미리보기 전체가 하나의 링크(`<a href="/world/fishing">`, 접근 이름 `펨타듀 낚시 들어가기`). 캔버스에 터치 처리를 걸지 않으므로 스크롤이 막히지 않는다.
- 미리보기 아래 모서리에 작은 글자로 `들어가기` 표시(설명 없이 이름만 있는 버튼 원칙과 같은 무게).
- `user_records`가 실패하면 기본 옷차림·기본 지역으로 그린다. 그리기 자체가 예외를 던지면 미리보기 자리에 `펨타듀 낚시 들어가기` 버튼 하나를 그린다. 버튼 묶음은 영향받지 않는다.

## 6. 열린 지역 기록

- 미리보기가 잠긴 문을 열린 것처럼 그리지 않도록 `WorldLogic.avatar`와 같은 방식으로 기록 하나를 더한다.
- `WorldLogic.previewData?(state): Record<string, string>`: 미리보기에 쓸 짧은 값들. 낚시는 `{ areas: state.areas.join(',') }`.
- `world` 핸들러: 값이 바뀌었을 때만 `game_records`에 키마다 행(값 0, `detail` = 문자열)을 upsert한다(`avatar`와 같은 규칙, 처음 불러올 때도 채움).
- 기록 탭(`RecordsSection`)은 manifest `records`에 선언된 키만 그리므로 이 행은 보이지 않는다. 등록부 테스트: `previewData`의 키가 `records` 키와 겹치지 않는다.
- 낚시 `logic.version`은 올리지 않는다(세이브 형식·판정 불변). `world` 함수 재배포가 필요하다.
- 배포 뒤 낚시를 한 번 열기 전까지는 기본 지역만 열린 것으로 그린다. 그 사람이 다른 지역에 저장돼 있으면 마을 시작 위치에 선다(§5.2). 감수한다.

## 7. 없애는 것

- `src/platform/home/`의 블록 6개(`blocks/*`), `EditList`, `layout.ts`, `blocks.ts`와 테스트.
- RPC `set_home_layout`과 `profiles.home_layout` 컬럼은 **이번에는 남긴다**(**내 판단**: 되돌릴 일이 생겨도 저장값이 살아 있게. 정리는 다음 마이그레이션에서). 화면에서만 안 쓴다.
- `/games` 화면, 상단 내비게이션, 리더보드·프로필은 그대로다. 블록에서 보던 순위·레이팅·기록은 그곳에 이미 있다.
- `CLAUDE.md`·홈 대시보드 설계 문서에 "대체됨" 표시를 단다.

## 8. 구현 단계

한 PR(`feat/home-valley`)로 충분하다. 순서:
1. 등록부: `Manifest.preview`, `WorldLogic.previewData`, `getWorldPreview`, 등록부 테스트.
2. `world` 핸들러의 `previewData` 기록과 테스트(`fn:test`).
