# 펨타듀 낚시 — 걸어 다니는 마을 설계 (2026-11-23)

상태: **승인 대기**

## 1. 의도

지금은 부두 끝 고정 화면에서 제자리 낚시만 한다. 캐릭터가 작은 바닷가 마을을 걸어 다니며 물가 어디서나 낚시하고, 물고기는 상점 건물까지 걸어가서 팔게 바꾼다.

사용자가 정한 비중: **산책·탐험의 재미 7 : 판매하러 오가는 수고 3.** 걷기는 즐거워야 하고, 오가는 수고는 "가방이 차면 한 번 다녀온다" 정도로 느껴지면 된다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 화면보다 큰 타일맵 마을. 카메라가 캐릭터를 따라간다.
- 폰: 가상 조이스틱으로 이동하고 행동 버튼 하나로 상호작용. 데스크톱: 방향키나 WASD로 이동하고 스페이스가 행동.
- 물을 바라보고 물가에 서면 어디서나 낚시할 수 있다. 부두 끝에서 던지면 큰 개체가 더 잘 나온다.
- 상점 건물 문 앞에서만 상점(판매, 낚싯대·가방 구매)이 열린다.
- 상점에서 가방 업그레이드를 판다: 20 → 30 → 40칸.

**비목표**
- 건물 내부 화면, NPC, 낮과 밤, 날씨, 계절
- 맵 여러 장, 배, 선착장 (지금 타일맵 구조로 나중에 붙일 수 있게만 둔다)
- 서버의 위치 추적·검증
- 대각선 전용 스프라이트 (이동은 대각선 가능, 그림은 주된 축 방향을 쓴다)
- 다른 플레이어가 맵에 보이는 기능

**실패 조건 (동작해도 실패)**
- 폰에서 조이스틱을 쓰다 화면이 스크롤되거나 확대되거나 글자가 선택된다.
- 물이나 건물 안으로 걸어 들어갈 수 있다. 맵 밖으로 나갈 수 있다.
- 낚시 버튼이 물을 등지고도 뜨거나, 물가에서 안 뜬다.
- 상점이 상점 앞이 아닌 곳에서 열린다. (화면 기준. 서버는 위치를 모른다, 6.3)
- 기존 세이브의 골드·낚싯대·도감·가방이 사라진다.
- 걷는 동안 프레임이 눈에 띄게 끊긴다 (폰 기준).
- 원작 게임의 그림이나 맵을 베꼈다.

## 3. 접근 방식

**맵 표현**
| | 방식 | 판단 |
|---|---|---|
| **A** | **글자 격자 타일맵 + 16px 타일 단위 충돌** | **채택.** 고치기 쉽고, 물가 판정·도달 가능성·충돌을 테스트로 검증할 수 있다. 다음 낚시터도 줄 몇 개로 추가된다. 지형이 각지는 건 감수한다. |
| B | 통그림 + 별도 충돌 영역 | 그림과 충돌 영역 두 벌이 어긋나기 쉽다. |
| C | 게임 엔진 라이브러리 | 새 의존성 금지(CLAUDE.md), 규모 대비 과하다. |

**부두 보너스 판정**
| | 방식 | 판단 |
|---|---|---|
| **A** | **클라이언트가 캐스팅 때 `spot`을 보내고 서버는 믿는다** | **채택.** 조작해서 얻는 이득은 부두까지 걸어간 것과 같다. 미니게임 성공 여부를 믿는 것과 같은 선이다. |
| B | 서버가 이동을 추적·검증 | 요청 수가 몇십 배, 지연 증가. 보너스 하나에 과하다. |

## 4. 마을과 조작

### 4.1 맵
- 크기: 가로 40~56, 세로 30~40 타일(16px). 화면 3~4개 분량.
- 구성: 위쪽은 풀밭 마을(상점 건물, 나무, 꽃, 울타리, 돌, 길), 가운데는 모래사장, 아래는 바다. 바다로 뻗은 나무 부두 하나.
- 상점 건물: 여러 타일짜리 건물, 문 하나. 문 바로 아래 타일에 서서 위(문 쪽)를 보면 상호작용 지점이 된다.
- **거리**: 부두 끝에서 상점 문 앞까지 걸어서 약 **8초** (초기 설계는 10~15초였으나 사용자 요청으로 이동 속도를 1.5배로 올림, 4.3). 너무 직선 통로가 되지 않게 길이 살짝 돌아가도 된다.
- 시작 위치: 상점 문 앞. 마지막 위치는 브라우저에 저장해 두고 다시 들어오면 거기서 시작한다(6.4).
- 맵은 원작 게임의 맵을 따라 그리지 않는다. 그림은 전부 새로 그린다.

### 4.2 타일 종류 (최소)
| 기호 예 | 타일 | 걸을 수 있음 | 비고 |
|---|---|---|---|
| `~` | 물 | ✕ | 2프레임 물결 (기존 물 타일 재사용 가능) |
| `.` | 모래 | ○ | |
| `,` | 풀 | ○ | |
| `=` | 길 | ○ | |
| `#` | 부두 | ○ | 부두 끝 판정에 쓴다 |
| `T` | 나무 | ✕ | 장식 |
| `f` | 꽃·풀포기 | ○ | 장식 |
| `|` | 울타리 | ✕ | 장식 |
| `o` | 돌 | ✕ | 장식 |
| `B` | 상점 건물 | ✕ | 건물 그림은 여러 타일 크기 스프라이트 하나로 그려도 된다 |
| `D` | 상점 문 | ✕ | 문 아래 타일이 상호작용 지점 |

기호와 종류는 빌더가 바꿔도 된다. 단, 걷기 가능 여부와 상호작용 규칙은 위 표대로.

### 4.3 이동
- 속도: 초당 4.5타일(72px/s, 처음 48px/s에서 사용자 요청으로 1.5배). 조이스틱 끝까지 밀면 최고 속도, 살짝 밀면 느리게. 데스크톱 키는 최고 속도.
- 대각선 이동은 된다. 대각선 속도도 최고 속도를 넘지 않는다(정규화).
- 충돌: 캐릭터 발 부분의 작은 사각형(예: 10×6px)을 기준으로, 걸을 수 없는 타일과 겹치지 않게 축별로 따로 밀어낸다(벽을 따라 미끄러지게).
- 바라보는 방향: 마지막으로 움직인 주된 축의 4방향(위·아래·왼쪽·오른쪽).
- 프레임 간격(dt)은 기존 미니게임처럼 상한을 둔다(탭이 백그라운드에서 돌아올 때 순간이동 금지).
- 낚시 중(게이지 충전부터 결과 표시까지)과 메뉴가 열려 있을 때는 움직이지 않는다.

### 4.4 상호작용 (행동 버튼 / 스페이스)
캐릭터가 서 있는 타일과 바라보는 방향의 바로 앞 타일로 정한다.
- 앞 타일이 **상점 문**이면 → **"상점"**: 누르면 상점 메뉴가 열린다.
- 앞 타일이 **물**이면 → **"낚시"**: 지금의 캐스팅 흐름 그대로(누르고 있으면 게이지, 떼면 던짐 → 입질 → 챔 → 미니게임). 챔과 미니게임 중 누르기도 같은 버튼(또는 화면 아무 곳)이다.
  - 서 있는 타일이 **부두**면 `spot: 'pier'`, 아니면 `spot: 'shore'`.
- 둘 다 아니면 행동 버튼은 흐리게 비활성.

### 4.5 화면
- 카메라: 캐릭터를 화면 가운데에 두되 맵 가장자리에서는 멈춘다(맵 밖 검은 영역이 보이지 않게). 맵이 화면보다 작은 축은 가운데 정렬.
- 장면 크기: 지난번에 만든 `fitScene`(정수 배율, 논리 크기 가변)을 그대로 쓴다.
- 찌: 바라보는 방향으로 캐스팅 세기에 비례한 거리(약 1.5~5타일)에 떨어진다. 그 사이에 물이 아닌 타일이 있으면 그 직전 물 타일까지만 간다.
- 미니게임 트랙, 충전 게이지, 입질 느낌표, 낚음·놓침 표시는 화면 고정(HUD) 위치에 그린다. 캐릭터를 가리지 않는 쪽(캐릭터가 화면 왼쪽 절반이면 오른쪽에)에 둔다.
- 조이스틱: 캔버스 위 왼쪽 아래에 반투명 원. 누른 자리를 중심으로 생기는 떠다니는 조이스틱이어도 된다(빌더 재량). 행동 버튼: 오른쪽 아래 큰 원형 버튼, 글자로 "낚시"/"상점".
- 아래 버튼 줄: 가방, 도감, 전체화면. **상점 버튼은 없앤다**(상점 앞에서만 열린다). 상점에서 떨어져 있을 때 가방 패널에 "상점에서 팔 수 있어요" 안내.
- 데스크톱(포인터가 마우스)에서는 조이스틱과 행동 버튼을 숨기고 하단에 "방향키로 이동 · 스페이스로 낚시/상점" 안내.
- 텍스트 선택·스크롤 방지는 기존 `game-screen` 처리와 캔버스 `touch-action: none`으로 덮는다. 조이스틱과 행동 버튼도 `touch-action: none`.

### 4.6 캐릭터 그림
- 4방향 걷기: 방향마다 정지 1장 + 걷기 2장. 기존 정면 그림을 아래 방향으로 쓴다.
- 낚시 자세(던지기, 감기): 아래·위·옆 3방향. 왼쪽은 오른쪽을 좌우 반전.
- 새 타일 그림: 풀, 길, 나무, 꽃, 울타리, 돌, 상점 건물(문 포함), 모래와 풀 경계, 물과 모래 경계(가장자리가 자연스럽게).

## 5. 규칙 변경 (서버 로직)

### 5.1 부두 보너스
- `cast` 행동에 `spot: 'pier' | 'shore'` 추가. 없거나 모르는 값이면 `'shore'`로 본다(옛 클라이언트 호환).
- `pier`면 크기 추첨에 쓰는 세기를 `min(1.25, power + 0.25)`로 올린다. 지금 공식 `p = rng() ** (1.5 - power)` 그대로라 큰 개체가 더 잘 나온다. 어종·등급 확률은 그대로다.
- `rollCatch` 시그니처에 보너스를 받을 인자를 더한다. rng 호출 순서와 횟수는 바꾸지 않는다.

### 5.2 가방 업그레이드
- state에 `bagTier: 1 | 2 | 3` 추가. 칸 수는 1단계 20, 2단계 30, 3단계 40.
- 새 행동 `buyBag { tier }`: 바로 다음 단계만, 가격 2단계 **800 G**, 3단계 **5,000 G**. 골드만 차감(누적 수익은 그대로). 오류 코드는 낚싯대와 같은 꼴: `bad_tier`, `not_enough_gold`.
- `cast`의 `bag_full` 판정이 `BAG_SIZE` 대신 현재 단계 칸 수를 쓴다.
- 상점 메뉴에 가방 업그레이드 항목 추가(낚싯대 목록과 같은 모양). 가방 표시 `n/칸수`.

### 5.3 로직 버전
- `logic.version` 1 → 2.
- `migrate`: `bagTier`가 없으면 1. 나머지는 지금 규칙 그대로.
- `data.ts`·`logic.ts`가 바뀌므로 배포 때 `world` 함수를 다시 배포해야 한다(CLAUDE.md "낚시 데이터 갱신").

## 6. 기술 설계

### 6.1 파일
- `src/games/fishing/map.ts` (신규, 순수): 맵 글자 격자, 타일 표, `isWalkable(tx, ty)`, `tileAt`, `interactionAt(pos, facing): 'shop' | { fish: 'pier' | 'shore' } | null`, `castTarget(pos, facing, power)`(찌 위치), 시작 위치.
- `src/games/fishing/walk.ts` (신규, 순수): 이동·충돌 `stepWalk(player, input, dtMs) → player`, 카메라 `cameraFor(player, view, map)`, 조이스틱 벡터 계산.
- `scene.ts`: 고정 장면 대신 타일맵 + 카메라로 그린다. 정적 타일 레이어는 지난번처럼 오프스크린에 캐시하되, 맵 전체를 한 번 그려 두고 카메라 영역만 잘라 그린다(맵 640~900px 폭이면 캐시 하나로 충분). 물 2프레임은 캐시 두 장.
- `Game.tsx`: 이동 상태와 입력(조이스틱, 행동 버튼, 키보드)을 기존 낚시 상태 기계 앞단에 붙인다. 기존 phase 흐름(cast → hook → resolve)은 그대로.
- `logic.ts`, `data.ts`: 5장 변경.

### 6.2 플랫폼
플랫폼 코드는 바꾸지 않는다. `world` 함수, 테이블, 기록 탭 모두 그대로.

### 6.3 서버가 모르는 것
캐릭터 위치. 그래서 "상점 앞에서만 판매·구매"와 "부두 보너스"는 화면과 클라이언트 신고에 의존한다. 조작으로 얻는 것은 걷는 수고를 건너뛰는 것뿐이고, 골드를 더 만들 수는 없다. 받아들인다.

### 6.4 위치 저장
마지막 위치와 방향을 `localStorage`(사용자 id별 키)에 저장. 읽기·쓰기는 try/catch, 실패하면 시작 위치. 저장된 위치가 걸을 수 없는 타일이면(맵이 바뀐 경우) 시작 위치로.

### 6.5 테스트
- `map.test.ts`: 모든 줄 폭이 같다, 모르는 기호 없음, 시작 위치는 걸을 수 있다, 상점 문 앞 상호작용 지점이 정확히 하나, 부두 끝에서 물을 향한 낚시 지점이 있다, 시작 위치에서 부두 끝·상점 문 앞·모든 물가 걷기 타일에 도달 가능(BFS), **부두 끝 ↔ 상점 문 앞 최단 경로가 30~45타일**(72px/s 기준 약 7~10초), 맵 테두리는 모두 걸을 수 없거나 물.
- `interactionAt`: 물 바라봄 → fish(shore), 부두에서 물 바라봄 → fish(pier), 문 아래에서 위 → shop, 그 외 null.
- `castTarget`: 세기 0/1에서 거리, 중간에 육지가 있으면 직전 물 타일.
- `walk.test.ts`: 대각선 속도 정규화, 벽을 따라 미끄러짐, 물·건물·맵 밖으로 못 나감, 큰 dt 상한, 카메라가 가장자리에서 멈춤, 맵이 화면보다 작은 축은 가운데.
- `logic.test.ts`: `spot` 없음·이상한 값 → shore와 같은 결과(같은 시드), pier는 평균 크기 백분위가 더 큼(시드 고정 다수 추첨), rng 호출 횟수 불변, `buyBag` 성공·순서 건너뛰기·잔액 부족·누적 수익 불변, 30칸 가방에서 21번째 cast 허용·31번째 bag_full, `migrate` 버전 1 세이브 → bagTier 1·골드 유지.
- `Game.test.tsx`: 행동 버튼 글자가 위치에 따라 낚시/상점/비활성으로 바뀜, 상점 버튼이 아래 줄에 없음, 키보드 이동, 낚시 중 이동 안 됨, cast 요청에 spot이 실림.
- `world/handler.test.ts`의 실제 등록부 한 바퀴: cast에 spot 추가, buyBag 한 번.
- 미리보기 PNG: 맵 전체 한 장, 폰 화면 크기에서 물가·부두 끝·상점 앞 세 장면.

## 7. 내가 정한 것 (사용자가 직접 고르지 않은 항목)
1. 건물 내부 없음, 문 앞에서 상점 메뉴
2. 부두 끝 ↔ 상점 약 8초 거리 (처음 10~15초, 이동 속도 1.5배로 변경)
3. 가방 20/30/40칸, 800/5,000 G
4. 가상 조이스틱 + 행동 버튼 하나, 데스크톱은 방향키·WASD + 스페이스
5. 부두 보너스 = 크기 추첨 세기 +0.25 (어종 확률은 그대로)
6. 서버는 위치를 검증하지 않음
7. 아래 버튼 줄에서 상점 버튼 제거
8. 마지막 위치는 브라우저에만 저장
9. 맵 크기 40~56 × 30~40 타일, 이동 속도 초당 3타일

## 7-1. 검토 뒤 정한 것
- 부두 보너스는 부두 끝만이 아니라 **부두 타일 어디서든** 물을 보고 던지면 붙는다(부두 옆면 포함). 부두로 걸어 나가는 것 자체가 보상이다.
- "가방이 가득 찼어요" 안내의 "상점 열기" 버튼은 없애고 "상점에 가서 팔아 주세요" 안내로 바꾼다.
- 위치 저장 키의 사용자 id는 로그인 세션(`useAuth`의 profile id)에서 얻는다.
- 새로고침·버전 변경 뒤 진행 중이던 캐스트는 버리고 저장 위치에서 대기 상태로 시작한다(`migrate`가 이미 pending을 비운다).
- 터치·마우스 구분은 `(pointer: coarse)` 미디어 쿼리로 한다.
