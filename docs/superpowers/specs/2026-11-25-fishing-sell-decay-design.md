# 낚시 판매 마릿수 감쇠·후반 가격 설계 (승인됨, 2026-11-25)

## 왜
2026-11-24 사이트 하루 상한을 75%·50%로 풀자(PR #96) 진행이 크게 빨라졌다(하루 1·3·5시간 = 23.0·9.4·5.9일).
골드 상한은 좋은 장비로 비싼 물고기를 잡을수록 빨리 걸려 "장비를 산 사람을 벌주는" 모양이었다.
판 마릿수는 장비와 거의 무관하게 플레이 시간에 비례하므로, 오래 하는 사람만 조이는 데 맞는 기준이다(사용자 제안).

## 결정 (사용자)
1. **마릿수 감쇠 K**: KST 하루에 판 물고기 n번째의 판매가 배율 — 1~150번째 100%, 151~300번째 50%, 301~450번째 20%, 그 뒤 5%.
   한 번에 여러 마리를 팔면 가방 순서대로 한 마리씩 적용한다. 물고기마다 `round(sellPrice × 배율 / 100)`.
2. **낚시 수입은 사이트 하루 상한에서 뺀다**: `_gold_move`의 상한은 reason `free`에만, `_earned_today`는 `free`·`daily_prize`만 센다.
   미니게임은 게임별 하루 상한(2,050, 2026-11-24 1/10)이 그대로 있다.
3. **후반 가격**(가시 바늘 다음 품목): 장비 ×1.6, 지역 해금 ×2.2, 갯벌은 그대로.
   백골 448,000 · 용왕 992,000 · 50칸 80,000 · 60칸 160,000 · 늪지 132,000 · 산정 호수 264,000 · 난파선 330,000 · 갯벌 30,000.

## 결과 (econSim, 사면 바로 사기·성공률 80%·약 196마리/시간 가정)
장비·해금 전부 사기까지: 하루 1·2·3·5·10시간 = 30.4 / 21.4 / 20.1 / 18.2 / 15.7일.

## 구현 범위
- `data.ts`: `SELL_DECAY`(구간 [마릿수 상한, 배율 %]), 가격.
- `logic.ts`: 세이브 `sold: { day: 'YYYY-MM-DD'(KST), n }`. 날짜가 오늘이 아니면 0으로 본다. `sell`이 감쇠를 적용하고 `sold`를 늘린다.
  `logic.version` 15. 옛 세이브는 `{ day: '', n: 0 }`. `totalEarned`는 감쇠 뒤 금액을 더한다.
- 화면: 상점의 예상 금액에 감쇠를 반영하고 "오늘 판 물고기 n마리 · 지금 판매가 x%"를 보인다. 가방 칸의 물고기 값은 감쇠 전 그대로.
- 마이그레이션: `_gold_move`(상한 reason `free`만), `_earned_today`(`world` 제외).
- `econSim`: 사이트 상한 대신 마릿수 감쇠로 하루를 잰다. 진행 속도 테스트를 새 값으로.
- 배포: DB push → `world` 함수 재배포 → Vercel.

## 비목표·남긴 것
- 잠금으로 비싼 물고기만 먼저 팔아 100% 구간을 쓰는 것은 의도한 동작이다(사용자, 2026-11-25). 가방 칸이 상한이다.
- 가방에 쌓아 두었다가 다음 날 팔기: 가방 칸이 상한이라 막지 않는다.
- 하루가 바뀐 뒤 화면의 예상 배율은 다음 서버 응답까지 옛 값일 수 있다(화면은 브라우저 시계로 날짜를 다시 본다).
