# 내 섬 B단계 설계 — 개간·재료·작업대

작성 2026-11-26. 상위 설계 `2026-11-25-my-island-design.md` §2의 B. 사용자는 "B·C·D를 차례로 쭉 진행"을 맡기고 잠들었다. 그래서 이 문서의 결정 대부분은 **Claude가 정했다**("내가 정한 것"). 사용자 결정은 상위 설계에 있는 것만 따로 적는다.

## 1. 왜 · 무엇을 느끼게

- 동물의 숲처럼: 무인도에 도구를 들고 가서 나무를 베고 돌을 캐고, 모은 재료와 골드로 섬을 조금씩 넓힌다.
- 매일 들를 이유(재료가 다시 나옴)와, 넓힐수록 재료가 더 나오는 성장 고리(내 추천, 사용자가 답하기 전에 잠듦 → 내가 정함).
- 친구가 놀러 오면 "많이 넓혔네"가 보인다.

## 2. 이미 정해진 것 (사용자 결정, 상위 설계)

- 도구 세 가지(도끼·곡괭이·삽), 재료 세 가지(나무·돌·철), 재료는 하루마다 다시 나온다.
- 덤불·나무·바위를 치워 쓸 칸을 넓힌다. 개간·짓기에는 **재료 + 골드**.
- 재료는 **팔 수 없다**(새 수입원 금지).
- 가격은 `base × n^p`(p 1.5~2) + 항목마다 최고 단계. 집·꾸미기까지 다 갖추는 데 하루 1시간으로 3개월 이상.
- 작업대가 있다. 섬 상태는 낚시 세이브의 `isle` 덩어리 안에.

## 3. 목표 · 비목표 · 실패 조건

**목표**
- 텐트 옆 작업대에서 도구를 만들고(1단계) 철로 올린다(2·3단계).
- 섬의 나무·바위 "자원 칸"을 보고 행동하면 하루 한 번 재료가 나온다(도구 단계만큼).
- 작업대의 "개간" 탭에서 다음 구역을 재료 + 골드로 치우면, 그 구역의 막힌 칸이 풀밭이 되고 새 자원 칸이 드러난다.
- 친구 섬에서도 그 친구가 치운 만큼 넓어진 섬이 보인다(구경만, 캐기 없음).

**비목표**
- 섬 낚시터(B 이후 따로, 어종 설계 필요 — 내가 정함: B에서 뺀다).
- 집(C), 꾸미기·가구(D), 수집(E). 작업대의 B 레시피는 도구뿐.
- 재료 팔기·주기·버리기. 손님이 남의 섬에서 캐기.
- 자원 칸이 오늘 캤는지 그림으로 보이기(안내 문구로만 — 내가 정함, 그림은 D 때 함께).

**실패 조건**
- 재료나 개간으로 골드가 생긴다(어떤 경로든).
- 서버가 확인하지 않고 재료가 늘어난다(같은 날 같은 칸 두 번, 없는 칸, 도구 없이, 남의 섬 칸).
- 옛 세이브(v22)를 읽지 못하거나, 섬을 고르지 않은 사람의 낚시가 막힌다.
- 개간한 뒤 걸어서 못 가는 자원 칸·작업대가 생긴다.

## 4. 접근

- **채택: 구역(zone) 단위 개간 + 고정 자원 칸 (내가 정함).** 섬마다 막힌 칸을 순서가 정해진 8구역으로 나눈다. 개간은 "다음 구역 하나"를 한 번에 치운다. 자원 칸은 섬 데이터에 미리 정해 두고, 구역이 치워질 때 드러난다. 서버는 구역 번호와 칸 id만 확인하면 되고, 가격이 곧 "단계 n" 곡선이 된다.
- 버림: 칸마다 하나씩 치우기 — 요청이 수백 번, 가격 곡선이 어색하고 걸어 닿는지 확인이 칸마다 필요하다.
- 버림: 자원 칸이 무작위로 다시 자라기 — 서버 난수·배치 저장이 필요하고 B에 비해 크다.

## 5. 상세

### 5.1 저장 상태 (`State.isle`, logic.version +1)
```
isle: {
  layout: 'crescent' | 'twin',
  cleared: number,            // 치운 구역 수 0..8 (순서대로)
  tools: { axe: 1..3, pick: 1..3, shovel: 1..3 },  // 처음 1
  mats: { wood, stone, iron },                       // 0..MAT_CAP(999)
  gathered: { day: string, ids: string[] },         // 오늘(KST) 캔 자원 칸 id
} | null
```
- migrate: v22의 `{layout}`은 `cleared 0, tools 0, mats 0, gathered {day:'', ids:[]}`. 모르는 값·범위 밖은 기본값으로.

### 5.2 섬 데이터 (`isle.ts`, 순수)
- 섬 모양마다 `nodes: { id, tx, ty, kind: 'tree'|'rock'|'iron', zone: 0..8 }[]`, 작업대 고정물.
- 구역은 사각형이 아니라 계산한다(내가 정함): 7칸 넘는 나무·바위 덩어리만 개간 대상(작은 덩어리는 그대로 두고 그중 몇 칸이 처음 자원 칸), 덩어리를 작은 것부터, 덩어리 안은 걸을 수 있는 땅에서 가까운 칸부터 줄 세워 8등분한다. 이 순서라 구역 k의 칸은 늘 이미 닿는 칸 옆이다. 치우면 풀밭(`,`).
- 자원 칸: 나무 칸(도끼 → 나무), 바위 칸(곡괭이 → 돌), 철광(곡괭이 → 철). zone 0은 처음부터 닿는 칸. 구역 k를 치우면 zone k 칸이 닿게 된다.
- 맵: `isleMap(layout, cleared = 0)`이 치운 구역을 반영한 `MapDef`를 돌려준다(모양·치운 수마다 한 번 만들어 둔다). 자원 칸은 맵의 `nodes`로 나가고, 그 칸을 보면 `{ kind: 'node', id, res }` 상호작용.
- 검사(시험): 각 모양에서 cleared 0..8마다 그때 드러난 모든 자원 칸과 작업대 앞이 배에서 내리는 칸에서 걸어 닿는다.

### 5.3 행동 (서버 `apply`)
- `gather { id }`: 섬을 골랐고, 그 id가 자기 섬 모양의 자원 칸이고, 그 zone ≤ cleared, 오늘 안 캔 칸이면 재료 +도구 단계(나무 → 도끼, 돌·철 → 곡괭이). 날이 바뀌면 `gathered`를 비운다. 오류: `no_isle`, `bad_node`, `node_locked`, `gathered`, `mats_full`(상한 999, 넘는 만큼은 버리지 않고 거절).
- `craft { tool, tier, price }`: tier = 지금 + 1(2 또는 3), 최고 3. 재료·골드 확인. `price`가 서버 값과 다르면 `price_changed`(낚싯대 구매와 같은 규칙).
- `clear { zone, price }`: zone = cleared + 1 ≤ 8. 구역 요구 도구(5.4). 재료·골드 확인. 오류 `bad_zone`, `need_tool`, `not_enough_mats`, `not_enough_gold`, `price_changed`.
- 남의 섬에서는 이 행동을 보내지 않는다(화면). 서버는 자기 세이브에만 쓰므로 남의 섬을 바꿀 수 없다.
- 날짜는 `kstDay(ctx.now)`(판매 감쇠와 같은 하루).

### 5.4 가격 (내가 정함, `economy` 기준 `REF = 20,500`)
- B 전체 골드 목표 ≈ `REF × 30`(약 615,000). 3개월 목표(`REF × 120`) 중 B는 첫 한 달쯤.
- 개간 구역 k(1..8): 골드 `floor10(REF/4 × k^1.7)`, 재료 나무 `8k`, 돌 `6k`, 철 `k ≥ 3`이면 `3(k−2)`. 구역 5부터 도끼·곡괭이 2단계, 7부터 삽 2단계가 필요.
  - 골드: 5,120 / 16,650 / 33,180 / 54,140 / 79,090 / 107,800 / 140,000 / 175,800 → 합 약 611,800.
- 도구: **1단계는 섬을 고르면 처음부터 가진다**(첫날부터 캘 수 있게 — 내가 정함). 2단계 나무 10·철 5·골드 4,000, 3단계 나무 20·철 15·골드 16,000. 세 도구 합 골드 60,000.
- 하루 재료 감: 처음 나무 칸 4·바위 3 → 하루 나무 4·돌 3. 구역마다 자원 칸 1~2개가 드러난다. 도구 3단계·전부 개간이면 하루 대략 나무 30·돌 24·철 8.
- 검사: `gold.test.ts`처럼 "B 골드 총액이 `REF × 30` ±15%" 시험을 둔다.

### 5.5 화면
- 작업대: 텐트 오른쪽 옆 고정물(내 섬에서만 행동, 남의 섬은 A 규칙대로 고정물 행동 없음). 행동 이름 "작업대". 창 제목 "작업대", 탭 두 개:
  - **도구**: 도끼·곡괭이·삽마다 지금 단계와 다음 단계 재료·골드, "만들기"/"올리기".
  - **개간**: 다음 구역 번호(k/8), 필요 재료·골드·도구, "개간하기". 다 치웠으면 "섬을 모두 개간했어요".
  - 맨 위에 가진 재료 `나무 n · 돌 n · 철 n`.
- 자원 칸 앞: 행동 이름 "캐기"(나무면 "베기"). 성공하면 잠깐 안내 `나무 +2`, 실패는 `오늘은 다 캤어요`/`도끼가 있어야 해요` 등.
- 개간 성공: 창을 닫고 같은 맵 안 페이드(밀물 옮기기와 같은 방식)로 넓어진 섬을 그린다, 안내 `개간했어요 (k/8)`.
- 친구 섬: `publicView`에 `cleared`를 더해 그만큼 넓어진 섬을 그린다.

### 5.6 미리보기·기록
- 기록 `isle_cleared`(값 = cleared, 프로필 "기록" 탭에 "섬 개간 k/8"). manifest `records`에 추가.
- 메인 미리보기: 기록 `isle` detail에 `layout:cleared`를 담는다(예 `twin:3`). 옛 값 `twin`은 0으로 읽는다.

## 6. 제약

- 상위 설계 §6과 같다. `logic.ts` 순수, 버전 +1, migrate 시험, `world` 재배포. DB 변경 없음(기록은 `game_records` upsert로 충분 — `world_players`는 key `isle` 그대로).
- 다른 세션이 낚시 버전을 또 올렸으면 리베이스하며 한 칸 더 올린다.

## 7. 빌더에게 맡기는 것
- 구역 사각형과 자원 칸 정확한 위치(시험을 통과하는 배치).
- 작업대 그림(텐트 옆 작은 스프라이트), 창 배치.

## 내가 정한 것 (사용자 확인 필요)
1. 섬 낚시터를 B에서 뺐다.
2. 개간은 순서가 정해진 8구역(계산으로 나눔), 한 번에 한 구역.
3. 자원 칸은 고정 위치, 하루 한 번, 캔 상태 그림 없음.
4. 가격 수치 전부(§5.4)와 B 골드 총액 `REF × 30`.
5. 도구 1단계는 처음부터 가진다, 삽은 개간(구역 7·8)에만 쓴다.
6. 재료 상한 999, 넘으면 캐기 거절.
