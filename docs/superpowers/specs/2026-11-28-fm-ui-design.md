# 사이트 화면 FM 스타일 개편 설계

작성 2026-11-28. 시안: Design 캔버스 "onlyfms 디자인 방향 시안"의 "FM 스타일" 페이지(머리글·개요·게임·대전·순위·대회·프로필·제안·밸리).

## 1. 왜
사용자 평: "디자인이 너무 AI스럽다". 짚은 점은 네 가지다.
- 같은 모양 카드의 반복
- 똑같은 알약 버튼
- 글꼴 하나뿐
- 사이트 개성이 없음

남보라·분홍 같은 색 조합은 문제로 꼽지 않았다. 컨셉 시안 8개와 "지금 사이트 다듬기"는 거절했다("유치하다, 지금 사이트와 너무 다르다, 컨셉질 하지 마"). 평소 좋아하던 FM24 기본 UI 결의 시안은 "좋다"고 했다. 진행 방식은 **화면별로 시안대로 한꺼번에(2번)**를 골랐다.

## 2. 목표 · 비목표 · 실패 조건

**목표**
- 머리글과 화면 7개(홈, 게임, 대전, 순위, 대회, 프로필, 제안)를 시안의 FM 결로 바꾼다.
  - 숯빛 바탕 위에 한 톤 밝은 판을 겹치고, 판마다 작은 제목 띠를 붙인다.
  - 모서리는 4px로 각지게 하고, 글자를 촘촘히(본문 13–15px) 둔다.
  - 목록은 표·줄로 보여 주고, 내 줄은 왼쪽 강조색 띠로 표시한다.
  - 대전 결과는 승·무·패 작은 칸으로 보여 준다.
  - 채운 버튼은 화면마다 1–2개로 줄인다.
- 다른 화면(데일리·자유 플레이, 대회 상세, 대국 화면, 관리자 등)은 공통 부품(카드·버튼·입력·배지·표)을 같은 결로 바꿔서 어색하지 않게 맞춘다.
- 모든 팔레트(10개 × 다크·라이트)에서 그대로 동작한다.

**비목표**
- `src/games/**`(게임 코드, 단 §4.3의 `shortName` 두 줄은 예외), world 함수, 펨타듀 밸리 게임 화면 안쪽(아래 메뉴 격자 포함). 낚시 작업이 진행 중이라 충돌을 피한다. 밸리 화면은 낚시 작업이 끝난 뒤 따로 한다.
- 로고와 사이트 이름(`Brand.tsx`): 글꼴, 크기, 전역일 문구와 번갈아 보이는 동작까지 지금 그대로 둔다.
- 서버, DB, RPC, `logic.version`.
- 팔레트 색 값과 목록, 화면 설정(AppearanceSettings) 기능.
- 시안의 "받은 소식" 판. 소식을 모아 둔 데이터가 없어서 뺀다.

**실패 조건**
- 지금 할 수 있는 동작이 사라지거나 클릭 수가 늘어난다. 데일리 시작, 대국 만들기·참가, 순위 기간·게임 바꾸기, 제안 쓰기·투표·삭제, 대회 만들기, 프로필 탭이 해당한다.
- 팔레트를 바꿨을 때 글자 대비가 무너진다(라이트 모드 포함).
- 휴대폰(390px)에서 머리글이나 탭이 넘친다.
- 낚시 작업 파일과 충돌한다.

## 3. 접근
- **채택(사용자 선택):** 화면별 마크업을 시안대로 바꾼다. 공통 부품은 `theme.css`에 새 클래스(`fm-*`)로 추가하고, 기존 공통 클래스(`.card`, `.btn`, `.input`, `.badge`, `.table`, `.list-row`)도 같은 결로 고친다.
- **버린 안:** 공통 부품만 바꾸고 화면 구조는 단계적으로 고치는 안. 충돌은 적지만 사용자가 고르지 않았다.

## 4. 상세

### 4.1 색 (토큰만)
새 색 값은 만들지 않는다. `theme.css`의 `:root`에 토큰을 섞은 파생 변수를 둔다(내가 정함).
- `--fm-head`: `color-mix(in srgb, var(--panel), var(--ink) 6%)`. 판 제목 띠.
- `--fm-line`: `color-mix(in srgb, var(--panel), var(--ink) 12%)`. 판 안 구분선.
- `--fm-me`: `color-mix(in srgb, var(--panel), var(--accent-strong) 12%)`. 내 줄 바탕.
- 승·무·패 칸(내가 정함, 빌더 확인 반영): **테두리형**으로 그린다. `--panel` 바탕에 1px 테두리를 두고, 글자와 테두리 색을 같게 한다. 승은 `--win-text`, 패는 `--lose-text`, 무는 `--muted`. 채움형은 기본 보라 라이트에서 `--on-accent` 글자 대비가 3.1–3.5로 기준(4.5)에 못 미친다. 테두리형은 20개 조합 모두 5.1 이상이다. 취소된 대국(`void`)은 칸에서 뺀다.

팔레트 시험(`palettes.test.ts`)이 파생 변수의 대비를 보지 않으므로, 새 시험을 둔다. 판 바탕 위 본문·흐린 글자와 `--fm-head` 위 제목 글자가 대비 기준을 넘는지 10개 팔레트 × 다크·라이트로 확인한다. `color-mix`는 시험 안에서 같은 식으로 계산한다.

### 4.1b 글꼴
글꼴은 바꾸지 않는다(내가 정함). 본문은 Pretendard, 사이트 이름은 Exo 2다. 시안도 새 글꼴을 쓰지 않았다. "글꼴 하나뿐"이라는 지적은 판 제목 띠(11px 굵게), 본문(13–15px), 숫자(16–18px 굵게, `tabular-nums`)의 크기·굵기 위계로 푼다. 새 글꼴 의존과 `main.tsx` 변경은 없다.

### 4.2 공통 부품 (`theme.css`에 추가)
- `.fm-panel`: `--panel` 바탕, radius 4px, 테두리 없음.
- `.fm-panel-head`: 판 제목 띠. 11px 굵게, `--muted`, `--fm-head` 바탕, 오른쪽 끝에 보조 링크·정보.
- `.fm-row`: 판 안 한 줄. 왼쪽 이름·보조 글자, 오른쪽 값·`›`. 최소 높이 44px, 줄 사이 `--fm-line`.
- `.fm-table`: 표. 머리줄 11px `--muted`. 내 줄은 `.is-me`(`--fm-me` 바탕 + 왼쪽 3px `--accent-strong`).
- `.fm-stats`: 숫자 칸 격자(이름 11px, 값 16–18px 굵게, `tabular-nums`).
- `.fm-form`: 왼쪽 이름표, 오른쪽 입력. 폰에서 이름표 폭 72px.
- `.fm-seg`: 라디오 두세 개를 붙인 구분 버튼. 실제 `input type=radio` + `label`이라 접근성은 지금 라디오와 같다.
- `.fm-chip`: 승·무·패 작은 칸(18px).
- `.fm-tabs`: 판 안 글자 탭. 선택은 밑줄 2px `--accent-strong`.
- 버튼은 기존 `.btn-primary`(채움), `.btn-ghost`(테두리)를 radius 4px로 고친다. `.btn-text`(글자 링크형)를 새로 둔다.
- 기존 `.card`는 radius 14→6px, 그림자를 줄인다. `.list-row`, `.notice`, `.input`, `.badge`도 radius를 4–6px로 맞춘다. 값은 내가 정한다.

### 4.3 머리글 (`Layout.tsx`, `UserMenu.tsx`)
**첫 줄**
- 왼쪽: `<Brand />`(그대로).
- 오른쪽: `WalletBadge`, 밸리 바로가기 버튼, 계정 버튼(아바타 글자 하나).
- 밸리 버튼은 등록부에서 `manifest.preview`가 있는 지속형 게임을 찾아 연결한다. `HomePage`와 같은 규칙이고 게임 id로 분기하지 않는다. 없으면 버튼을 두지 않는다.
- 라벨은 `manifest.shortName ?? manifest.name`이다(사용자 결정: 말줄임 대신 짧은 이름). `Manifest` 타입(`src/games/types.ts`)에 선택 필드 `shortName?: string`을 추가하고, 낚시 manifest(`src/games/fishing/manifest.ts`)에 `shortName: '밸리'` 한 줄을 넣는다. `src/games/**`에서 바꾸는 곳은 이 두 줄뿐이다. 접근 이름은 `${manifest.name} 들어가기`다.

**둘째 줄: 탭**
- 홈, 게임, 대전, 순위, 대회, 제안 6개. "리더보드" 탭 이름은 "순위"로 바꾼다. 주소(`/leaderboard`)는 그대로다.
- "관리자"는 계정 메뉴 안으로 옮기고, 결정 대기 숫자 배지도 같이 옮긴다.
- 높이는 시안처럼 약 76px. 위아래 여백과 탭 높이를 줄인다. 탭 누르는 영역은 최소 40px.

**넓은 화면(900px 이상)**: 지금처럼 머리글 안쪽 폭 1100px.

### 4.4 화면별
각 화면 맨 위의 큰 페이지 제목(`.page-title`)은 탭과 겹치므로 시각적으로 숨기고(`sr-only`), 제목 요소는 남긴다.

- **홈**(`HomePage.tsx`, `Shortcuts.tsx`, `home.css`). 판을 위에서부터 이 순서로 둔다.
  1. 밸리 판: 지금 미리보기 컴포넌트를 그대로 쓴다(정사각형, 접속 중 친구 요약 포함). 제목 띠는 게임 이름, 오른쪽 "입장 ›".
  2. 오늘 판: 데일리 게임마다 "데일리 ○○ · 아직 안 풀었어요/오늘 N점", 내 대국 N개, 진행·예정 대회 N개. 지금 `Shortcuts`의 표시 데이터를 쓴다.
  3. 오늘 순위 판: `lb_daily(p_day=오늘, p_game=null)` 위 3명. 내가 4위 밖이면 내 줄을 덧붙인다. "전체 ›"는 `/leaderboard`로 간다.
  4. 최근 대전 판: `duel_list().recent` 앞 3개와 승·무·패 칸 5개. 끝난 대국이 없으면 판을 숨긴다. `duel_list`는 내 대국 표시와 한 번만 부른다.
  5. 게임 판: 자유 플레이 게임 줄 목록.
  - 각 판은 따로 불러오고, 실패하면 그 판만 "불러오지 못했어요"를 보인다.
- **게임**(`GamesPage.tsx`, `UpcomingContests.tsx`): 주제 구역을 판으로 만든다. 게임은 판 안 줄이다.
  - 데일리 게임: 이름, 설명, 오늘 상태, `[데일리]`(채움 작게), `[자유]`(테두리 작게).
  - 자유 플레이만 있는 게임: 줄 전체가 링크.
  - 지속형 게임: "입장 ›".
  - 넓은 화면의 대회 옆 열(`split-aside`)과 구역 배치 규칙(컨테이너 쿼리)은 유지한다.
- **대전**(`DuelHomePage.tsx`, `StakePicker.tsx`, `OptionSelects.tsx`):
  - 맨 위 숫자 칸: 대기실 n, 내 대국 n.
  - 새 대국 판은 `.fm-form`으로 만든다. 종류(랭크/친선)와 공개 범위는 `.fm-seg`, 판돈 칩은 4px 각진 칩, 만들기 버튼은 채움 한 개.
  - 대기실·내 대국·최근 결과 판: 최근 결과는 표(칸, 상대·게임, 점수·판돈)다.
  - 같은 화면 대결 판은 줄 목록이다.
- **순위**(`LeaderboardPage.tsx`, `LbTable.tsx`, `DuelBoard.tsx`, `leaderboard.css`):
  - 보기 6개(오늘·주간·전체·대회·자유 플레이·대전)는 **`.fm-tabs`** 한 줄로 둔다. 지금처럼 한 번 눌러 바꾸고, 폰에서 넘치면 가로로 밀린다(빌더 확인 반영: select로 바꾸면 클릭이 늘어 §2 실패 조건에 걸린다). 상태 모델과 RPC, 보기별로 게임 칸을 숨기는 규칙은 지금 그대로다.
  - 게임 고르는 칸은 지금처럼 `<select>`다.
  - 표는 `.fm-table`이다. 판 제목 띠에는 보기 이름과 인원을 두고, 게임을 고른 보기면 "보기 · 게임"으로 쓴다.
  - 대회·자유·대전 보기의 표도 같은 부품으로 바꾼다.
- **대회**(`ContestListPage.tsx`): 오른쪽 위 "대회 만들기"(채움). 진행 중·예정·종료 판을 두고, 각 판은 표(대회, 종류, 시작 시각)다.
- **프로필**(`ProfilePage.tsx`, 각 Section, `profile.css`):
  - 머리 판: 아바타, 이름, 골드, 보너스 줄.
  - 숫자 칸 격자.
  - 탭(요약·퍼즐·대전·기록·설정)은 `.fm-tabs`.
  - 각 섹션 안 목록은 `.fm-table`이나 `.fm-row`.
  - 다른 사람 프로필의 상대 전적 등 지금 있는 블록은 모두 남긴다.
- **제안**(`SuggestPage.tsx`, `suggest.css`):
  - 맨 위 한 줄: 대상 `<select>`(지금 대상 칩 줄을 대신한다), 정렬은 최신·공감순 `.fm-seg`. 대상을 고르면 글쓰기 대상도 같이 바뀌는 지금 동작은 유지한다.
  - 글쓰기 양식은 접지 않는다(빌더 확인 반영: 접으면 쓸 때마다 클릭이 는다). 대신 한 줄 높이의 입력칸으로 작게 두고, 누르면 여러 줄로 커지며 "올리기" 버튼이 나타난다. 지금처럼 바로 눌러 쓴다.
  - 글 목록 판의 한 글에는 대상, 상태 칩(기각/반영 예정 등), 본문, 답글(왼쪽 선), 작성자, 삭제·투표가 있다.
  - 관리자 결정 칸은 그대로 둔다.

### 4.5 시험
- 기존 화면 시험은 역할·이름으로 찾으므로 대부분 그대로 통과해야 한다. 구조 변경으로 바뀌는 이름(탭 "리더보드"→"순위", 관리자 링크 위치, 제안 대상 칩→select)은 시험을 함께 고친다.
- 새 시험:
  - 머리글: 탭 6개와 순서, 계정 메뉴의 관리자 항목과 배지, 밸리 버튼(지속형 게임이 있을 때만).
  - 홈: 판 5개, 오늘 순위 위 3명 + 내 줄, 최근 대전 칸, 판별 실패 표시.
  - 순위: 보기 탭이 `.fm-tabs`로 바뀌어도 탭을 누르면 해당 RPC를 부른다(지금 시험 유지).
  - 제안: 대상 select가 글쓰기 대상을 바꾼다, 입력칸을 누르면 커지고 올리기 버튼이 보인다.
  - 대전: 구분 버튼(라디오)으로 종류·공개 범위를 고른다.
  - 팔레트 파생 변수 대비(§4.1).
- `npm test && npm run typecheck && npm run build`.

## 5. 제약
- CLAUDE.md 규칙을 따른다: 모든 문구는 한국어, 모바일 우선, 색은 theme.css·palettes.ts 토큰만, 플랫폼 코드에 게임 id 분기 금지.
- 낚시 작업과 충돌을 피한다: `supabase/**`는 바꾸지 않는다. `src/games/**`는 `types.ts`와 `fishing/manifest.ts`의 `shortName` 두 줄만 바꾼다. `theme.css`는 주로 끝에 덧붙이고 기존 규칙은 꼭 필요한 곳만 고친다.
- 화면별 커밋으로 나눠서, 충돌이 나도 화면 단위로 풀 수 있게 한다. 번들을 만들기 직전에 최신 main 위로 다시 쌓는다.
