# 내 섬 설계 (펨타듀 밸리) — 전체 그림 + A단계 상세

작성 2026-11-25. 근거: 대화 결정(사용자). 앞선 메모 `specs/2026-11-24-house-land-notes.md`의 "개인 집터"를 이 설계가 대신한다.

## 1. 왜 만드나

- 같이 노는 것은 마을회관에 모았다. 개인 공간은 **혼자 키우는 곳**이다(사용자 결정).
- 동물의 숲처럼: 사람마다 무인도 하나를 받아 개간하고, 집을 키우고, 바깥을 꾸미고, 모은다. 친구 섬에 놀러 가서 "많이 컸네"를 본다.
- 성장 세 갈래(땅 넓히기, 집, 꾸미기·수집)를 모두 한다(사용자 결정).

## 2. 전체 그림 (프로젝트 나누기)

| 단계 | 이름 | 내용 | 비고 |
|---|---|---|---|
| **A** | 내 섬 기반 | 섬 모양 고르기, 배로 내 섬·친구 섬 가기, 무인도 + 텐트, 친구 섬 구경, 같은 섬 사람끼리 보이기 | **이 문서에서 상세** |
| B | 개간·재료·작업대 | 도구(도끼·곡괭이·삽), 재료(나무·돌·철, 하루마다 다시 나옴), 덤불·바위 치우기로 쓸 칸 넓히기, 작업대 레시피 | 가격은 어종 다양화 머지 뒤 계산 |
| C | 집 | 텐트 → 오두막 → 집 → 방 추가, 방 안 가구 놓기 | |
| D | 바깥 꾸미기 | 길·울타리·꽃·야외 가구를 칸마다, 나중에 밭 | |
| E | 수집 | 과일나무, 꽃 교배, 전시 | |
| (B 이후) | 섬 낚시터 | 개간을 많이 하면 섬에 낚시 자리가 열린다 | 어종은 그때 따로 |

모든 단계에 걸리는 규칙(사용자 결정):
- **재료를 모아 만든다**(동물의 숲처럼). 재료는 **팔 수 없다**(새 수입원을 만들지 않는다. 지갑 설계의 "새 수입원은 사이트 하루 상한 안에" 규칙을 건드리지 않기 위해).
- 개간·짓기·업그레이드에는 **재료 + 골드**를 함께 쓴다.
- **가격 원칙 변경**: 기하급수 대신 **완만한 곡선 `base × n^p`(p 1.5~2) + 항목마다 최고 단계**. "하루 1시간으로 다 갖춘 느낌까지 3개월 이상"은 유지하고, 항목 전체 총액을 낚시 수입에 맞춘다. 지갑 설계 §15를 이에 맞게 고친다.
- **작업대(만들기)를 넣는다.**
- 섬에서 낚시는 처음엔 안 되고, 개간이 진행되면 "섬 낚시터"가 열린다.

## 3. A단계 목표 · 비목표 · 실패 조건

**목표**
- 처음 내 섬에 가면 섬 모양 2개 중 하나를 고르고(바꿀 수 없음), 그 섬에 텐트가 서 있다.
- 마을 선착장에서 배를 타고 목적지를 고른다: 낚시 지역 "섬"(지금처럼 배를 사야 열림), 내 섬(무료), 친구 섬(무료).
- 친구 섬은 주인이 접속하지 않아도 갈 수 있고, 구경만 한다.
- 같은 섬에 있는 사람끼리 서로 보이고 자랑·이모트·말풍선이 된다.
- 섬에서 배를 타면 마을 선착장으로 돌아온다.

**비목표 (B 이후)**
- 도구, 재료, 개간, 작업대, 집 업그레이드, 가구, 바깥 꾸미기, 수집, 섬 낚시터.
- 손님이 남의 섬에서 무언가를 바꾸기(줍기·베기·놓기).

**실패 조건**
- 남의 세이브 전체(가방·지갑·장비 등)가 구경하는 사람에게 내려간다.
- 옛 세이브를 읽지 못하거나, 섬을 고르기 전 세이브에서 낚시가 막힌다.
- 플랫폼 코드에 게임 id 분기가 생긴다.
- 지금 낚시 지역 "섬"(`island`)과 내 섬이 이름·지역 id에서 헷갈린다.

## 4. 접근 방식

- **1. 낚시 게임 안의 새 지역 `isle` + 주인별 상태를 낚시 세이브 안에 (채택, 사용자 결정).** 캐릭터·옷·지갑·가방·말풍선·페이드를 그대로 쓰고, B단계의 "재료 + 골드" 거래를 한 세이브에서 한 번에 처리한다. 섬 상태는 세이브 안의 한 덩어리(`isle`)로 묶어, 나중에 커지면 3으로 옮길 수 있게 한다.
- 2. 섬을 별도 world 게임으로: 캐릭터·채팅·같은 장소 보기를 다시 만들어야 하고 흐름이 끊긴다.
- 3. 섬 상태를 새 테이블에 따로: 구경은 쉬우나 저장소가 둘이 되어 함께 맞춰야 하고, `WorldLogic` 계약과 마이그레이션이 바뀐다.

## 5. A단계 상세

### 5.1 섬과 이름
- 지역 id `isle`, 이름: 내 섬이면 **"내 섬"**, 남의 섬이면 **"{아이디}의 섬"**. 지금의 낚시 지역 `island`(이름 "섬")는 그대로 둔다.
- `isle`은 낚시 지역이 아니다(`spots` 빈 배열, 마을회관과 같은 규칙: `FISHING_AREAS`에서 빠진다). 큰 지도 탭에도 넣지 않는다(`onWorldMap: false`).
- 장소 = **지역 + 주인**. `isle`만 주인이 있고, 나머지 지역은 주인이 없다.

### 5.2 섬 모양 (2종)
- 두 모양 모두 48×36칸 안팎, 같은 규칙을 따른다(사용자 결정: 몇 가지 중 고르기, 처음 2개):
  - 남쪽 바닷가에 선착장(배 타는 곳), 도착 칸은 선착장 앞.
  - 선착장 가까이 텐트 자리(고정 칸).
  - 섬 안쪽은 B단계에서 치울 덤불·나무·바위가 덮고 있다. A단계에서는 이것들이 **그냥 막힌 칸**이다(치우기는 B).
  - 처음 걸을 수 있는 땅: 바닷가 모래와 텐트 둘레 정도.
  - 강·연못 같은 물은 넣어도 되지만 A에서는 낚시가 안 된다.
- 모양 이름(예: "초승달 섬", "쌍둥이 만 섬")과 그림은 빌더가 정한다. 픽셀 그림은 마을회관처럼 생성기(`scripts/`)로 만들어도 되고 기존 타일로 짜도 된다.
- 고르는 창: 처음 내 섬에 도착하면(또는 배에서 "내 섬"을 처음 고르면) 두 모양의 작은 그림과 이름, "고르면 바꿀 수 없어요" 안내, 고르기 버튼.

### 5.3 저장 상태 (낚시 세이브)
- `State.isle: { layout: IsleLayoutId } | null`. A단계는 모양 하나만 저장한다(텐트 자리는 모양마다 고정). B 이후 이 안에 치운 칸·놓은 물건이 들어간다.
- 서버 행동 `isleChoose { layout }`: 이미 골랐으면 `already_chosen`, 모르는 모양이면 `bad_layout`. 낚는 중이면 `busy`.
- `previewData`에 키 `isle`(값 = 모양 id)을 **고른 뒤에만** 넣는다(설계자 판단). 이 기록 행이 (1) 친구 목록의 "섬이 있는 사람" 기준, (2) 메인 미리보기가 섬 모양을 아는 근거가 된다.
- `logic.version`을 올리고 옛 세이브는 `isle: null`. `world` 재배포.

### 5.4 친구 섬 구경 (플랫폼 + 게임)
- **플랫폼 계약 추가**(게임 id 분기 없음):
  - `WorldLogic.publicView?(state): unknown` — 남에게 보여도 되는 값만. 낚시는 `{ isle, outfit }` 정도(섬 모양, 나중의 칸 상태, 주인 옷).
  - `world` 함수 요청 `{ game, action: 'visit', owner: <사용자 id> }` → 주인의 세이브를 읽어 migrate만 하고(**쓰지 않는다**) `{ owner: { id, handle }, view: publicView }`를 돌려준다(설계자 판단: 아이디는 바뀔 수 있어 id로 찾는다). 승인된 사용자만, 주인도 승인 상태여야 하고, 숨김 게임이면 관리자만. 세이브가 없으면 `no_save`, `publicView`가 없는 게임이면 400.
  - 화면용 데이터 계층 함수 `worldVisit(game, owner)`(`src/lib/api.ts` 옆, 기존 `world` 호출 방식).
- **친구 목록**: 새 RPC `world_players(p_game text, p_key text)` → 그 게임에서 `game_records` 키 `p_key` 행이 있는 승인 사용자 `[{ id, handle, avatar }]`(본인 제외, 아이디 순, avatar는 같은 게임의 `avatar` 행 detail). 숨김 게임은 관리자만. 낚시는 `p_key = 'isle'`로 불러 **섬을 고른 사람만** 보인다(설계자 판단: 섬이 없는 사람은 목록에서 뺀다). 플랫폼은 키의 뜻을 모른다.
- 낚시 화면은 받은 `publicView`로 남의 섬 맵을 그린다. 남의 섬에서는 고정물 행동을 하지 않는다(A에는 고정물이 텐트·배 정도뿐: 텐트 "살펴보기" 안내만).

### 5.5 배 (마을 선착장)
- 지금 마을 선착장 행동은 "열렸으면 낚시 섬으로 출발, 아니면 배 구매 창"이다. 이를 **목적지 창**으로 바꾼다:
  - **섬(낚시)**: 열렸으면 출발, 아니면 지금 배 구매 창으로.
  - **내 섬**: 출발. 아직 모양을 안 골랐으면 도착 뒤 고르는 창.
  - **친구 섬**: 친구 목록(`world_players`)에서 골라 출발. 출발 전에 `visit`로 섬을 받아 둔다(실패하면 출발하지 않고 안내).
- 섬의 선착장에서 배를 타면 마을 선착장 앞으로 돌아온다(목적지 창 없이).
- 내 섬·친구 섬 배는 무료(사용자 결정). 서버 행동이 필요 없다(장소 이동은 지금도 화면이 정한다).

### 5.6 같은 장소 사람 보기·위치 저장
- 실시간 방 이름과 접속 상태(presence)의 장소 값을 **지역 + 주인**으로 넓힌다: `isle-<주인 id에서 하이픈을 뺀 32자>`(설계자 판단). 장소 값 규칙 `^[a-z0-9-]{1,32}$`을 `{1,48}`로 넓힌다(플랫폼 변경, 게임 id와 무관).
- 다른 지역에 있는 친구 목록(큰 지도·메인 미리보기)에서 섬에 있는 친구는 "{주인}의 섬"으로 보인다. 이름은 화면이 장소 값의 id를 `world_players` 목록(본인 섬이면 "내 섬")에서 찾아 붙이고, 못 찾으면 "누군가의 섬"(설계자 판단: presence 형식은 바꾸지 않는다). 큰 지도 위 점은 그리지 않는다(섬은 세계 지도 밖).
- 위치 저장: 내 섬에서 나간 자리는 다시 들어올 때 이어서. **남의 섬 위치는 저장하지 않는다**(다시 열면 마을 시작 위치).

### 5.7 미리보기·기록
- 메인 미리보기: 저장 위치가 내 섬이면 기록 행 `isle`(5.3)로 모양을 알아 그 섬을 그린다. 행이 없거나(아직 기록 전) 모르는 모양이면 마을 시작 위치로 그린다. 맵 찾기(`mapFor`·시작 위치 판정)는 섬일 때 모양을 함께 받는다.
- 프로필은 바꾸지 않는다.

## 6. 제약

- 모든 문구 한국어, 모바일 우선. 캔버스 내부 색은 예외, 그 밖은 theme 토큰.
- `logic.ts` 순수, 상대 import `.ts`. 판정·저장 형식이 바뀌면 `logic.version` 올림 + migrate 테스트 + `world` 재배포.
- DB 변경은 `npx supabase@2 migration new`로 만든 마이그레이션만(`world_players`).
- 플랫폼(`src/platform/**`, `supabase/functions/world/`)은 게임 id를 보지 않는다.
- **동시 진행 중인 "낚시터 어종 다양화"와 겹친다**: `logic.version`, `data.ts`, `sprites.ts`. A 구현은 어종 다양화가 머지된 뒤 시작하는 것을 권한다(머지 순서·버전 번호가 단순해진다). B의 가격 계산은 반드시 그 뒤.

## 7. 빌더에게 맡기는 것

- 섬 모양 2종의 이름·생김새·정확한 칸, 그림 만드는 방법.
- 목적지 창·고르는 창의 배치와 문구.
- `publicView`에 넣을 정확한 필드(남에게 보여도 되는 것만).
