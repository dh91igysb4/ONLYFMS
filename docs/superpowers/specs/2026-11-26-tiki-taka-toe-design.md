# 티키타카토 (`tiki-taka-toe`) 설계

- 날짜: 2026-11-26
- 상태: 초안 (사용자 승인 전)
- 관련: 대전 플랫폼 `2026-11-01-duel-platform-design.md`, 축구 데이터 계층 `2026-11-01-football-data-layer-design.md`, 1987 확장 `2026-11-25-football-history-clubs-design.md`, 우승·수상·감독 `2026-11-25-football-honours-design.md`

## 1. 왜

축잘알 친구들끼리 1대1로 붙는 축구 틱택토다. 원작(playfootball.games Tiki Taka Toe, 사용자가 준 SICKWOLF 플레이 영상)을 규칙 그대로 옮긴다. 축구 DB(`football_*`)를 처음 쓰는 게임이다. 친구들은 1980년대 후반부터 아는 사람들이라 옛 선수·우승·감독 조건이 들어가야 재미있다(그래서 우승·수상·감독 수집을 먼저 했다).

### 성공 기준
- 두 사람이 온라인 대전(초대·공개 대국, Elo)과 한 화면 대전(같은 폰 돌려 쓰기, 원작 Pass & Play)으로 끝까지 둘 수 있다.
- 칸마다 그 칸 조건을 둘 다 만족하는 선수를 자동완성으로 골라 넣고, 판정이 축잘알이 보기에 맞다.
- 판이 너무 어렵거나(정답 없는 칸, 무명 선수만 정답인 칸) 너무 쉽지(정답 수백 명) 않다.

### 하지 않는 것
- 원작의 Grid Builder(조건을 번갈아 고르기), Suspensions(상대 선수 금지), 희귀도 점수. 나중에 옵션으로 붙일 수 있다.
- 데일리·대회·자유 플레이(혼자 하기). 대전만.
- K리그 테마. 사용자가 고른 테마 목록에 없다(§3.3).
- 한글 선수 이름 보강. 자동완성은 지금 `football_search`(한/영 별칭)를 그대로 쓴다.

### 실패로 보는 것
- 맞는 답을 틀렸다고 하거나 틀린 답을 맞았다고 하는 판정이 자주 나오는 것.
- 아무도 못 채우는 칸, 너무 쉬워 고민할 게 없는 칸이 자주 나오는 것.
- 사이트 첫 로딩이 무거워지는 것(정답 목록을 브라우저 번들에 넣지 않는다).

## 2. 방식 비교 (2026-11-26 사용자 선택: 2)

대전 로직(`DuelLogic`)은 DB를 못 보는 순수 함수라 `init(rng, options)`만으로 판을 만든다. 문제와 칸별 정답을 어디서 가져오느냐로 나뉜다.

| | 방식 | 장점 | 단점 |
|---|---|---|---|
| 1 | 문제 묶음을 코드 파일로 | 플랫폼 변경 없음 | 정답 목록 때문에 수 MB, 등록부를 브라우저도 불러 첫 로딩이 무거움. 문제 수 제한으로 반복 |
| **2** | **문제 은행을 DB에 두고 판 시작 때 하나 뽑기** | 브라우저 부담 없음, 문제 많음, 생성기를 TS로 테스트·조정 | 대전 플랫폼에 일반 기능 하나 추가, 데이터 갱신 때 생성 단계 하나 |
| 3 | 판 시작 때 SQL로 바로 생성 | 무한·항상 최신 | "칸마다 정답 3명 이상이면서 너무 쉽지 않은 조합" 탐색을 SQL로 짜야 해 복잡·느림·테스트 어려움 |

## 3. 규칙

### 3.1 한 판 (사용자 결정)
- 3×3 판. 가로 3개·세로 3개 머리칸에 조건이 하나씩. 칸에 놓으려면 그 칸의 가로·세로 조건을 모두 만족하는 선수를 댄다.
- 차례에 할 수 있는 것: 칸 하나를 골라 선수를 댄다(자동완성으로 고른 선수 id).
  - 맞으면 그 칸이 내 것. 틀리거나 시간이 지나면 그냥 상대 차례로 넘어간다.
- 턴 시간 제한은 판을 만들 때 고른다(플랫폼 `turnSeconds` 선택지).
- 스틸: 상대가 차지한 칸에 그 칸 조건을 만족하는 다른 선수를 대면 칸을 뺏는다. 먼저 두는 사람은 판당 5번, 나중에 두는 사람은 6번.
- 가로·세로·대각선 한 줄 3칸을 먼저 만들면 이긴다.

### 3.2 내가 채운 규칙 (사용자에게 보여 줌, 2026-11-25~26 이의 없음)
- 한 판에서 이미 쓴(맞게 놓인) 선수는 다시 못 쓴다. 칸이 달라도. 틀린 답으로 낸 선수는 다시 낼 수 있다.
- 스틸 실패(틀림)도 스틸 1회를 쓴다. 공짜 재시도를 막는다.
- 뺏긴 칸을 다시 뺏는 것도 스틸 횟수가 남아 있으면 된다.
- 9칸이 다 찼는데 줄이 없으면 무승부. 스틸이 남아 있어도 끝난다.
- 끝나면 칸마다 가능했던 정답 예시를 보여 준다(인지도 순 최대 5명).
- 선공은 무작위(서버 난수). 턴 시간 선택지 15·30·60초, 기본 30초.
- 스틸 횟수가 0이면 상대 칸은 고를 수 없다(화면에서 막고 로직도 거절).

### 3.3 턴 넘기기·무승부 제안·막힌 판 (2026-11-26 사용자 결정)
- **턴 넘기기(스킵):** 내 차례에 아무것도 안 하고 넘길 수 있다. 시간 초과도 턴 넘기기로 처리한다.
- **무승부 제안(체스처럼):** 내 차례에 행동하면서(칸에 답하기·턴 넘기기와 함께) 무승부를 제안할 수 있다. 상대는 자기 차례에 "수락"하면 바로 무승부로 끝나고, 다른 행동을 하면 거절한 것이다. 제안은 다음 상대 행동 한 번 동안만 유효하다. 한 사람이 연속으로 계속 제안하지 못하게, 거절당한 뒤 자기 차례 한 번은 다시 제안할 수 없다(내 결정).
  - 대전 플랫폼 공통 기능이 아니라 이 게임 로직의 행동으로 둔다(요트처럼 무승부 제안이 어색한 게임도 있어서, 내 결정). 턴 기반이라 상대 차례에 받는 방식이 지금 플랫폼에 그대로 맞는다.
- **막힌 판:** 연속 6턴(각자 3번) 동안 칸 주인이 하나도 바뀌지 않으면 끝난다. 칸을 더 많이 가진 쪽이 이기고, 같으면 무승부.

### 3.4 리그 테마 (2026-11-26 사용자 결정: 원작처럼 테마 선택)
판을 만들 때 고르는 manifest 옵션 `theme`: 잉글랜드 `eng` · 스페인 `esp` · 이탈리아 `ita` · 독일 `ger` · 유럽 전체 `eur`. 기본 `eur`.
- 클럽 조건은 그 테마 리그(전신 대회 포함)의 1부에 1987년 이후 한 시즌이라도 있었던 클럽에서만 나온다. `eur`는 대상 유럽 리그 9개(잉글랜드·스페인·이탈리아·독일·프랑스·네덜란드·포르투갈·튀르키예·벨기에) 1부 클럽 전체.
- 리그 조건·득점왕 조건도 테마 리그 쪽으로 기운다(`eur`는 전부). 국적·대륙·대표팀 대회·발롱도르·감독은 모든 테마에 나온다.

## 4. 조건 종류와 판정 데이터

조건은 "선수 집합"이다. 칸 정답 = 가로 집합 ∩ 세로 집합. 모든 집합은 1987년 이후 기록으로 만든다(`season_memberships.csv` 1987~, `honours`·`manager_spells`).

| 종류 | 예시 머리칸 | 집합 정의 |
|---|---|---|
| 클럽 `club` | 아스널 | 그 클럽 시즌 소속이 한 시즌이라도 있는 선수(임대 포함) |
| 국적 `nation` | 프랑스 | `players.nation_id` |
| 대륙 `continent` | 남미 | 국적 나라의 대륙(아래) |
| 리그 경력 `league` | 세리에 A | 그 시즌 그 리그(1부) 참가팀 소속이 한 시즌이라도 있는 선수 |
| 팀 동료 `teammate` | 즐라탄과 뛴 선수 | 기준 선수와 같은 시즌 같은 클럽 소속(기준 선수 본인 제외). 기준 선수는 인지도 최상위 일부만 |
| 우승 `title` | PL 3회 이상 우승 / UCL 우승 / 월드컵 우승 | `football_honours` 선수 단위 우승 행 수 ≥ N (리그는 1 또는 3, 그 밖은 1) |
| 대표팀 대회 출전 `squad` | 월드컵 출전 | `squad:<대회>` 행 |
| 개인상 `award` | 발롱도르 / PL 득점왕 | `award:<id>` 행 |
| 감독 `manager` | 벵거 감독 | 클럽: 감독 재임 시즌 ∩ 선수 시즌 소속(같은 클럽). 대표팀: 재임 중 대회 엔트리 |
| 월드컵 결승 득점 `final_goal` | 월드컵 결승 득점 | `final_goal:Q19317` 행 |

- **같은 시즌 판정의 정밀도 (내 결정):** 경력 기록 대부분이 연 단위라, 팀 동료·감독 조건은 우승과 같은 규칙을 쓴다. 그 시즌 클럽 소속이 둘 이상인 선수(시즌 중간 이적·반 시즌 임대)는 그 시즌을 세지 않는다. 클럽·리그 경력 조건은 "한 시즌이라도 소속"이라 이 제외를 하지 않는다.
- **잉글랜드 1992년 전 (내 결정):** "PL"이 붙은 조건(PL 우승, PL 득점왕)은 1992년 이후 프리미어리그만. 별도로 "잉글랜드 1부 우승"·"잉글랜드 1부 득점왕"은 1987~91 풋볼리그 1부와 PL을 합친다(1부 시기만, `competition_eras.csv`).
- **국적 (2026-11-26 사용자 결정):** 선수마다 하나(`players.nation_id`, 대표팀 기준). 이중 국적은 지금 세지 않는다(예: 페페·데쿠는 포르투갈만). 시비가 나오면 따로 모은다.
- 대륙: `nations.confederation`이 비어 있어 생성기가 나라→대륙 표를 직접 입력 파일로 둔다(`data/football/manual/nation_continents.csv`, 유럽·남미·북중미·아프리카·아시아·오세아니아).
- 머리칸 이름은 한글: 클럽은 `teams.name_ko`(없으면 짧은 이름 → 영문), 상·대회·감독은 `honour_catalog.name_ko`, 리그는 `competitions.name_ko`, 나라는 `nations.name_ko`.
- 머리칸 모양(원작처럼 문장형): "PL 3회 이상 우승", "벵거 감독", "즐라탄과 뛴 선수", "월드컵 출전".

## 5. 문제 은행

### 5.1 생성기 `scripts/tiki-taka-toe/generate.ts` (`npm run ttt:generate`)
축구 CSV(`data/football/`)를 읽어 세 파일을 쓴다(`data/tiki-taka-toe/`):
- `conditions.csv`: `id,kind,label_ko,label_en,ref` — 쓸 수 있는 조건 목록. `ref`는 클럽·나라·대회·감독 id 등.
- `condition_players.csv`: `condition_id,player_id` — 조건별 선수 집합.
- `puzzles.csv`: `id,theme,r1,r2,r3,c1,c2,c3` — 판(머리칸 조건 id 6개). 테마마다 1,000판(내 결정, 조정 가능).

판 고르기 규칙(내 결정, 생성기 테스트로 고정):
- 9칸 모두 정답 수가 3 이상 150 이하.
- 9칸 모두 인지도(`popularity`) 50 이상인 정답이 2명 이상(무명만 정답인 칸 방지).
- 머리칸 6개 중 클럽이 3~4개(원작처럼 클럽 위주), 나머지는 다른 종류. 같은 종류가 한 축에 셋 다 오지 않게.
- 같은 조건이 한 판에 두 번 나오지 않는다. 판끼리 머리칸 6개가 똑같은 판은 없다.
- 조건 자체도 정답이 너무 많은 것(예: 국적 잉글랜드처럼 수천 명)은 클럽과 교차할 때 150을 넘기 쉬우므로 위 칸 규칙이 걸러 준다.

### 5.2 DB
새 마이그레이션: `ttt_conditions`, `ttt_condition_players`(인덱스 `(condition_id, player_id)`), `ttt_puzzles`. 클라이언트에서 직접 읽지 않는다(RLS로 막음).
적재는 축구 적재와 같은 방식의 스크립트(`scripts/tiki-taka-toe/load.sh` + `load.sql`, 한 트랜잭션 통째 교체). 축구 데이터를 다시 적재하면 생성 → 적재를 다시 한다(선수가 사라지면 FK로 실패해 알 수 있게 `player_id references football_players`).

RPC `ttt_pick_puzzle(p_options jsonb) returns jsonb` (security definer, 승인 사용자): `theme`에 맞는 판 하나를 무작위로 골라 `{ puzzle_id, rows: [{id,kind,label}], cols: [...], answers: [[player_id…] × 9] }`를 돌려준다(칸 순서 행 우선). 정답은 판 고를 때 `ttt_condition_players` 교집합으로 만든다. 각 칸 정답의 인지도 순 상위 5명 이름도 함께(끝난 뒤 공개용).

### 5.3 대전 플랫폼 일반 기능 "판 준비 RPC"
- manifest `duel.prepare?: string`(RPC 이름). 있으면 `duel` Edge Function이 대국을 시작할 때(지금 `logic.init`을 부르는 곳) 같은 트랜잭션에서 `select public.<prepare>(options)`를 불러 결과를 `init`에 넘긴다.
- 계약 변경: `DuelLogic.init(rng, options, prepared?: unknown)`. 기존 게임은 세 번째 인자를 무시한다.
- 한 화면 대전(`DuelLocalPage`)은 브라우저에서 `init`을 부르므로, `prepare`가 있으면 먼저 `supabase.rpc(prepare, { p_options })`를 불러 넘긴다.
- RPC 이름은 manifest의 값이라 게임별 분기 코드가 아니다. 이름은 `^[a-z_]+$`만 허용한다.
- 정답이 담긴 결과는 대국 상태(`duel_matches.state`)에만 있고, `view`는 끝나기 전 정답을 내보내지 않는다. 한 화면 대전이나 RPC를 직접 부르면 정답을 볼 수 있지만, 폰으로 검색하면 되는 게임이라 막지 않는다(내 판단).

## 6. 로직 (`src/games/tiki-taka-toe/logic.ts`)

- State: 머리칸, 칸별 정답 id 집합, 무승부 제안 상태(누가 제안했나, 다시 제안 못 하는 좌석), 칸 주인이 그대로인 연속 턴 수, 칸 주인(좌석·선수 id·선수 이름), 쓴 선수 집합, 남은 스틸 `[선공 5, 후공 6]`, 선공 좌석, 지금 차례, 수 번호, 마지막 행동(누가·어느 칸·누구를·맞음/틀림/스틸/패스), 결과.
- Action: `{ type: 'guess', cell: 0..8, playerId: string, name: string, offerDraw?: true }`, `{ type: 'pass', offerDraw?: true }`, `{ type: 'acceptDraw' }`(상대가 직전에 제안했을 때만). `name`은 화면 표시용(판정은 `playerId`로만).
- apply: 잘못된 행동(범위 밖 칸, 이미 쓴 선수, 스틸 0인데 상대 칸, 내 칸 재선택)은 `error`. 맞음/틀림은 정상 행동이고 차례가 넘어간다.
- timeoutAction: `{ type: 'pass' }`. turnNo: 수 번호.
- result: 줄 완성 → 그 좌석 승. 9칸이 다 찼고 줄 없음 → 무승부. 무승부 제안 수락 → 무승부. 막힌 판(§3.3) → 칸 많은 쪽 승, 같으면 무승부.
- view: 정답 집합은 끝나기 전 빼고, 끝나면 칸별 정답 예시(최대 5명 이름)를 넣는다.
- `logic.version` 1. 판정·문제 선택이 바뀌면 올린다(CLAUDE.md 로직 버전 규칙).

## 9. 검사
- 로직: 맞음·틀림·턴 넘기기·시간 초과, 무승부 제안(수락·다른 행동으로 거절·거절 뒤 한 번 재제안 금지·제안 없이 수락 거절), 막힌 판 6턴 판정, 스틸 횟수(선공 5·후공 6, 실패도 차감, 0이면 거절), 선수 재사용 거절, 줄 승리, 꽉 찬 무승부, view가 정답을 숨김.
- 생성기: 판마다 §5.1 규칙(칸 정답 3~150, 인지도 50 이상 2명, 클럽 3~4개, 중복 없음), 조건 집합 정의(클럽·리그·팀 동료·감독 겹침, 대륙 표) 단위 테스트.
- 플랫폼: `prepare`가 있는 게임은 시작 때 RPC 결과가 `init`에 들어감(Edge Function 테스트), 없는 게임은 그대로(요트 회귀).
- DB: `ttt_pick_puzzle`이 테마에 맞는 판·칸별 정답을 돌려주고, 비승인 사용자는 못 부름, 테이블은 직접 못 읽음.
- 수동: 테마별 몇 판을 뽑아 축잘알 눈으로 칸 정답이 맞는지(사용자와 함께).
