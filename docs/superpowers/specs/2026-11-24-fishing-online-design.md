# 펨타듀 밸리 온라인 — 같은 지역 친구 보이기 (1단계)

- 날짜: 2026-11-24
- 상태: **승인됨** (2026-11-24). 멈춰 있을 때 2.5초, 움직일 때 간격은 방 인원에 따라 동적으로(사용자 결정)
- 관련: `2026-11-23-fishing-world-design.md`(지역·맵), `2026-11-24-home-valley-design.md`(메인 미리보기)

## 1. 의도

지금 펨타듀 밸리(낚시 세계)는 혼자 하는 세계다. 친구들이 같은 세계에 있다는 느낌을 주려고, 다른 사람이 어디서 무엇을 하는지 보이게 한다.

사용자 범위(선택 2): 같은 지역에 있으면 서로의 캐릭터가 보이고(1단계), 다른 지역에 있어도 큰 지도와 메인 미리보기에서 친구 위치가 보인다(2단계). 이 문서는 1단계만 다룬다. 2단계는 메인 미리보기 PR(`feat/home-valley`)이 머지된 뒤 따로 설계한다.

**2단계 범위 (사용자 결정, 2026-11-24)** — 따로 설계한다:
- 큰 지도·메인 미리보기에 친구 위치 표시
- 말풍선·채팅·이모트
- 물고기 주고받기 (서버가 가방·지갑을 바꾸므로 서버 행동이 필요하다. 지갑 설계의 사이트 하루 상한·되팔기 금지 원칙과 맞춰야 한다)
- 대전 걸기 (만난 친구에게 기존 1대1 대전(판돈 포함)을 바로 신청)

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 같은 지역에 있는 친구 캐릭터가 지금 옷차림으로 보이고, 걷는 모습과 낚시 중인 자세가 보인다. 머리 위에 아이디.
- 움직임이 끊겨 보이지 않는다.
- 접속을 끊은 친구는 곧 사라진다.

**비목표**
- 캐릭터끼리 부딪히기
- 말풍선·채팅·이모트, 물고기 주고받기, 대전 걸기(2단계)
- 서버가 위치를 검증하거나 저장하기
- 큰 지도·메인 미리보기에 친구 표시(2단계), 접속 안 한 친구의 마지막 위치

**실패 조건 (동작해도 실패)**
- 실시간 연결이 안 되거나 끊겼을 때 혼자 하는 낚시가 멈추거나 느려진다.
- 친구가 그려지는 것 때문에 폰에서 프레임이 눈에 띄게 떨어진다.
- 낚시 판정·골드·세이브가 실시간 값에 영향을 받는다.
- 다른 지역에 있는 친구가 내 맵에 그려진다.
- 숨김 상태의 게임에서 관리자가 아닌 사람의 위치가 보인다.

## 3. 접근 방식

| | 방식 | 판단 |
|---|---|---|
| **A** | **Supabase Realtime 브로드캐스트로 위치, 프레즌스로 방 참여 관리** | **선택.** 대전·데일리 채팅이 이미 Realtime을 쓴다. 새 서버·DB 변경 없음 |
| B | 프레즌스만으로 위치까지 | 프레즌스 상태 갱신은 초당 여러 번 보내기에 무겁다 |
| C | 위치를 DB에 쓰고 변경 구독 | 걸음마다 DB 쓰기, 과하다 |

## 4. 설계

### 4.1 방
- 지역마다 채널 하나: `world:<gameId>:<areaId>` (예: `world:fishing:village`). 지역을 옮기면(맵 전환 페이드) 이전 채널을 나가고 새 채널에 들어간다.
- 공개 채널(대전과 같음). 프레즌스 키는 사용자 id.

### 4.2 보내는 것 (브로드캐스트 이벤트 `pos`)
```ts
type PeerState = {
  id: string; handle: string
  x: number; y: number            // 월드 픽셀, 발 중앙
  facing: 'up' | 'down' | 'left' | 'right'
  moving: boolean
  act: 'walk' | 'fish'            // 낚시 중(던지기~끝)이면 fish
  outfit: string                  // 옷차림 JSON(프로필 avatar와 같은 형식)
  t: number                       // 보낸 쪽 시각(ms), 순서 판단용
}
```
- 멈춰 있으면 **2.5초마다**(사용자 결정) 보낸다.
- 움직이는 동안의 간격은 **방 인원 n(프레즌스 기준, 나 포함)에 따라 동적으로**(사용자 결정): `moveIntervalMs(n) = max(250, ceil(1000 × n² / 80))`.
  | n | 2 | 3 | 4 | 5 | 6 |
  |---|---|---|---|---|---|
  | 간격(ms) | 250 | 250 | 250 | 313 | 450 |
  | 초당 | 4 | 4 | 4 | 3.2 | 2.2 |
  근거: 방 하나의 초당 메시지 ≈ n × (보낸 1 + 받은 n−1) × 초당 횟수 = n² × r. `r = min(4, 80/n²)`이면 6명이 어떻게 나뉘어도 모든 방 합이 초당 80 이하(6 / 5+1 / 4+2 = 80, 3+3 = 72)라 무료 한도 100에 여유가 남는다.
- 상태(방향·act·옷차림)가 바뀌면 바로 한 번 보낸다(단 그때 간격보다 자주 보내지 않음). 인원이 바뀌면 다음 보내기부터 새 간격.
- **방에 나 말고 아무도 없으면(프레즌스 기준) 보내지 않는다.** 대부분 혼자 있으므로 사용량이 크게 준다.
- 들어간 직후 한 번 보낸다(새로 온 사람이 곧바로 보이게).

### 4.3 받는 쪽
- 사람마다 마지막 두 위치를 두고 그 사이를 이어 그린다(보간, 받은 간격만큼 늦게 따라감). 순서가 뒤바뀐 메시지(`t`가 더 작음)는 버린다.
- 10초 넘게 소식이 없거나 프레즌스에서 빠지면 지운다.
- 내 메시지는 무시한다.
- 그리기: 친구 캐릭터를 내 캐릭터와 같은 그림(옷차림 합성 포함)으로, 내 캐릭터보다 먼저(아래 층에) 그린다. `act: 'fish'`면 낚싯대를 든 대기 자세. 찌·낚시 바는 그리지 않는다.
- 이름표: 캔버스 위에 HTML 글자로 띄운다(캔버스 픽셀 글꼴에 한글이 없음). 위치는 카메라 기준으로 프레임마다 맞춘다.

### 4.4 경계
- 실시간 연결 코드는 플랫폼 공통 모듈(`src/platform/world/`)에 게임을 모르게 둔다(방 이름에 gameId만 들어감). 낚시 화면이 그것을 불러 쓴다.
- 서버 판정·골드·세이브·`logic.version`·DB 변경 없음.
- 연결 실패·끊김은 경고 로그만 남기고 혼자 하는 게임은 그대로 둔다.
- 숨김 게임(`manifest.hidden`)이면 관리자만 방에 들어간다(관리자가 아니면 연결하지 않음).

### 4.5 사용량 (Supabase 무료 플랜, 2026-11-24 문서 기준)
- 한도: 동시 연결 200, 초당 메시지 100, 월 메시지 200만. 메시지 수에는 브로드캐스트·프레즌스가 모두 들어간다.
- 가정(추측): 보낸 메시지 1개가 보낸 1 + 받은 사람 수만큼 센다.
- 최악: 위 식으로 모든 방 합이 초당 80 이하(§4.2). 처음 설계한 고정 초당 5번이면 6명이 모일 때 180으로 한도를 넘어 연결이 끊긴다.
- 월: 혼자일 때 보내지 않으므로, 함께 있는 시간이 하루 1시간 플레이의 20%라고 보면 약 6 × 30 × 0.2시간 × (평균 약 3.5회/초 × 1/2 움직임 + 0.4회/초 × 1/2) × 3600 × 3 ≈ 140만 안팎. 한도 200만 안이지만 여유가 크지 않으므로 Supabase 대시보드의 Realtime 사용량을 배포 뒤 1주일 확인한다.

## 5. 내가 정한 것 (사용자 확인 필요)
- 공개 채널: 공개 키와 방 이름을 아는 사람은 아이디·위치를 볼 수 있다. 민감한 정보가 아니어서 받아들임. 막으려면 비공개 채널 + DB 정책이 필요하다.
- 숨김 게임이면 관리자끼리만 보인다.
- 소식이 끊긴 친구를 지우는 시간 10초.
