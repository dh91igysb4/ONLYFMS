# 볼 런 v2 — 원작 녹화에 맞춘 맵·조작감 개편 설계

작성: 2026-11-08. v1 설계(`2026-11-07-ball-run-design.md`)를 고친다. 여기 적지 않은 것은 v1을 따른다.
근거: 원작(앱 'Offline Games'의 공 굴리기, 어려움 모드) 화면 녹화 37초, 0.25초 간격 149프레임 분석.

## 1. 녹화에서 확인한 것

| 항목 | 원작 | v1 |
|---|---|---|
| 흐름 | 터널 → 급경사 내리막 → 장애물 구간 → 다시 터널이 반복. 첫 화면이 터널 안 | 조각 무작위 연결 |
| 속도 증가 | 터널 바닥 하늘색 화살표(가속 패드)를 지날 때 '속도 증가'와 공 뒤 마젠타 빛줄기. 약 8초마다 | 120 m마다 |
| 지형 | 전체가 내려간다. 판 사이 단차로 떨어져 착지, 경사 25~30° 정도 | 평지 위주, 경사 14° |
| 기울어진 판 | 폭 3칸 안팎의 좁은 판이 옆으로 기울어 이어지고 공이 아래쪽으로 밀린다 | 없음 |
| 장애물 | 1칸 블록, 높은 기둥(2~3 m), 문(마젠타 기둥 둘 + 남색 가로대), 양옆 마젠타 벽 통로, 1칸 레일 길 | 1 m 블록만 |
| 트랙 폭 | 기본 5칸, 좁아지면 1~3칸 | 같음 |
| 카메라 | 공 좌우 위치에 고정(공이 늘 화면 가운데 아래 ≈62%), 낮고 가깝다, 경사를 따라 숙인다 | x·y를 프레임마다 0.15씩 보간, 높고 멀다 |
| 점수 | 속도와 무관하게 0.5초에 1점 | 10 m에 1점 |
| 사망 | 공이 분홍·하늘·흰 조각으로 깨진다 | 축소 |

엔진 한계: 원작 길은 좌우로 휘지만 이 엔진은 z축 직선 트랙이다. 휘는 길은 열을 비스듬히 옮겨 가는 길(계단식 차선 이동)로 흉내 낸다.

## 2. 물리 변경 (`sim.ts`, `constants.ts`)

모든 값은 여전히 정수(mm, mm/틱, 틱).

### 2.1 좌우 관성
- `SimState`에 `vx`(mm/틱) 추가.
- 매 틱: `want = clamp(floor((target - x) / LAT_K), ±VX_MAX)`, `vx += clamp(want - vx, ±LAT_ACC)`. `LAT_K = 5`, `LAT_ACC = 25`, `VX_MAX = 117`(7 m/s). 손을 떼면(목표 유지) 공이 목표에 부드럽게 멈춘다.
- 기울어진 판은 쌓이는 `drift`(mm, 정수, `initSim`에서 0)로 민다. 직전 틱에 바닥에 있었고 공 중심 칸(이동 전 x, 새 z)이 기울었으면 `drift += bank × BANK_DRIFT`, `drift`는 ±2·`X_LIMIT`에서 멈추고 **줄지 않는다**(판이 공을 옮긴 것이지 되돌아오는 용수철이 아니다). 실효 목표 `clampX(target + drift)`를 위 식의 `target` 자리에 쓴다. `BANK_DRIFT = 80`: 3칸 판 가운데에서 손을 떼면 속도 1단계에서 6행 판 안(약 4.8행)에 판 밖으로 밀려나고, 손가락을 위쪽으로 틱마다 80 mm(4.8 m/s, 키보드 `KEY_STEP` 117보다 느림) 옮기면 제자리를 지킨다.
- 손가락 목표는 ±`X_LIMIT` 안이라 `drift`가 크게 남으면 반대쪽 끝에 못 간다. 그래서 모든 템플릿은 `<` 행 수와 `>` 행 수가 같다(조각 안 속도가 같으므로 조각을 지나면 `drift`가 거의 0으로 돌아온다, 시드 5개 봇 4분 주행에서 기운 판 밖 잔여 최대 0.8 m — 가운데 5칸 끝 열 가운데까지 여전히 닿는다). 화면은 이어 하기 때 `target = clampX(x − drift)`로 시작한다.
- 옆면 막힘이면 `x`는 이전 값, `vx = 0`.

### 2.2 단차·급경사
- 급경사 `!`: 한 행에 −500 mm(약 27°). 최고 속도에서 한 틱 바닥 하강 ≈ 234 mm이므로 `DROP_TOL = 260`으로 올린다.
- 단차 `v`: 그 칸에서 열 높이를 −1000 mm(평평). 공은 떨어져 날다가 아래 판에 착지한다.

### 2.3 속도 = 터널 수
- `SPEED_STEP_DIST` 삭제. `speedLevel = max(s.speedLevel, course.boostsBefore(rowOf(z)))`. `boostsBefore(row)`는 시작 터널을 뺀, 시작 행이 `row` 이하인 터널 조각 수.
- `SPEED_TABLE`: `V0 = 200`(12 m/s), 단계마다 ×1.06, 상한 `V_MAX = 467`(28 m/s). k번째 = `min(V_MAX, floor(200 × 106^k / 100^k))`, 상한에 닿은 뒤 1개까지.

### 2.4 블록 높이·기울기
- 칸에 선택 필드 `blockH`(mm, 기본 `BLOCK_H` 1000)와 `bank`(−1 왼쪽이 낮음 / +1 오른쪽이 낮음) 추가. 블록 충돌 높이는 `blockH`를 쓴다.
- 기울어진 판의 물리 바닥 높이는 칸 높이 그대로다(공 중심 기준). 기울기는 밀림과 화면에만 쓴다.

### 2.5 점수
- `score = min(SCORE_MAX, floor(tick / SCORE_TICKS))`, `SCORE_TICKS = 30`(0.5초에 1점). `SCORE_DIV` 삭제.
- 규칙이 바뀌므로 `logic.version = 2`.

## 3. 코스 변경 (`segments.ts`, `course.ts`)

### 3.1 DSL 추가 기호
| 기호 | 의미 |
|---|---|
| `!` | 급경사 내리막(이 행 −500 mm) |
| `v` | 단차(이 칸부터 열 높이 −1000 mm, 평평) |
| `<` / `>` | 평평한 기울어진 판. `<`는 왼쪽이 낮아 공을 왼쪽으로(`bank = −1`), `>`는 오른쪽으로(`bank = +1`) 민다 |
| `P` | 높은 기둥(바닥 + 블록, `blockH = 3000`) |
| `G` | 문 기둥(바닥 + 블록, `blockH = 2000`). 같은 행의 `G` 둘 사이에 화면용 가로대 |

좌우 반전 시 `<`·`>`는 서로 바뀐다(`bank` 부호 반전).

### 3.2 조각 종류
- `SegmentTemplate`·`ParsedSegment`·`SegmentInfo`에 `kind: 'tunnel' | 'descent' | 'obstacle'`. `decor: 'tunnel'`은 `kind: 'tunnel'`로 대체한다.
- 터널 조각: 가운데 5칸 `_`만(구멍·경사·단차·기울기·블록 없음), 길이 14~18행. 바닥에 가속 화살표, 양옆 마젠타 벽, 아치(화면).
- 내리막 조각: `!`·`\`·`v`로 크게 내려간다(조각당 −4 m 이상). 블록은 드물게.
- 장애물 조각: tier 1~4, 기존 종류 + 기둥·문·벽 통로(바깥 열 `B`/`P`로 3칸 통로)·1칸 레일·기울어진 좁은 판·비스듬히 옮겨 가는 길. 대체로 평평하거나 살짝 내려간다(`dh ≤ 0`).

### 3.3 생성 순서
- 첫 조각은 시작 터널(`START`, `kind: 'tunnel'`, 속도 단계에 세지 않음) → 내리막 → 장애물 `OBST_PER_STAGE = 3`개 → 터널 → 내리막 → …
- 장애물 tier 가중치는 거리 대신 **단계(지나온 터널 수)** 기준: `TIER_WEIGHTS = [{ fromStage: 0, w: [1,0,0,0] }, { fromStage: 1, w: [3,1,0,0] }, { fromStage: 3, w: [2,2,1,0] }, { fromStage: 5, w: [1,2,2,1] }, { fromStage: 8, w: [1,1,2,2] }]`.
- 터널·내리막은 각 풀에서 균등 추첨, 장애물은 최근 3개 중복 금지(v1과 같음), 모든 조각 좌우 반전 동전.
- 조각 추첨 난수 소비는 조각마다 고정 개수(종류와 관계없이 3개)로 유지한다.

## 4. 화면 변경 (`render/`)

- **카메라**: x는 공 x와 같다(보간 없음). y만 부드럽게(낙하·단차 흔들림 방지). 공 뒤 4.2 m, 위 1.7 m. 시선은 공 앞 6 m의 바닥 높이(없으면 공 높이) 쪽을 봐서 내리막에서 아래로 숙인다. 세로 화면에서 공이 화면 위에서 약 62% 지점에 오게 맞춘다.
- **기울어진 판**: 판을 z축으로 ±20° 돌려 그린다.
- **터널**: 기존 아치 + 양옆 발광 마젠타 벽 + 바닥 하늘색 화살표(CanvasTexture).
- **가속 연출**: `speedLevel`이 오르면 2초간 공 뒤로 반투명 마젠타 빛줄기.
- **기둥·문**: 블록 높이는 `blockH`. 같은 행 `G` 둘 사이 위에 남색 가로대(윤곽 라벤더).
- **사망**: `hit`이면 공을 24개 안팎의 작은 정육면체(분홍·하늘·흰)로 바꿔 1초간 흩어지게 한다. `fall`은 v1처럼 계속 떨어진다.
- **색**: 바닥 남색(#333877 안팎) + 굵은 라벤더 격자선(#9ea2ff 안팎), 판 옆면 라벤더. 녹화와 나란히 놓고 맞춘다.

## 5. 테스트·검증
- v1 테스트 구조 유지. 새 물리(관성, 기울기 밀림, 단차 착지, 급경사 접지, 터널 속도, 시간 점수)마다 단위 테스트.
- 코스: 단계 순서(터널 → 내리막 → 장애물×3) 고정 테스트, 반전 시 `bank` 부호 반전, 새 골든 스냅숏.
- 밸런스 게이트(v1 §7)를 새 템플릿 전부에 적용: 터널·내리막·장애물 각각을 원본·반전, 시작·최고 속도로. 시드 5개가 단계 10(터널 10개) 이상 통과.
- 헤드리스 Chrome 스크린숏을 녹화 프레임(터널, 내리막, 기운 판, 문, 블록 구간)과 나란히 비교.
