작성: 2026-11-08. v1 설계(`2026-11-07-ball-run-design.md`)를 고친다. 여기 적지 않은 것은 v1을 따른다.
근거: 원작(앱 'Offline Games'의 공 굴리기, 어려움 모드) 화면 녹화 37초, 0.25초 간격 149프레임 분석.

## 1. 녹화에서 확인한 것

| 항목 | 원작 | v1 |
|---|---|---|
| 흐름 | 터널 → 급경사 내리막 → 장애물 구간 → 다시 터널이 반복. 첫 화면이 터널 안 | 조각 무작위 연결 |
| 속도 증가 | 터널 바닥 하늘색 화살표(가속 패드)를 지날 때 '속도 증가'와 공 뒤 마젠타 빛줄기. 시작 ≈2.75초 뒤, 그다음 5~8초마다 | 120 m마다 |
| 지형 | 전체가 내려간다. 판 사이 단차로 떨어져 착지, 경사 25~30° 정도 | 평지 위주, 경사 14° |
| 기울어진 판 | 폭 3칸 안팎의 좁은 판이 옆으로 기울어 이어지고 공이 아래쪽으로 밀린다 | 없음 |
| 장애물 | 1칸 블록, 높은 기둥(2~3 m), 문(마젠타 기둥 둘 + 남색 가로대), 양옆 마젠타 벽 통로, 1칸 레일 길 | 1 m 블록만 |
| 트랙 폭 | 기본 5칸, 좁아지면 1~3칸 | 같음 |
| 카메라 | 공 좌우 위치에 고정(공이 늘 화면 가운데 아래 ≈62%), 낮고 가깝다, 경사를 따라 숙인다 | x·y를 프레임마다 0.15씩 보간, 높고 멀다 |
| 점수 | 속도와 무관하게 0.5초에 1점 | 10 m에 1점 |
| 사망 | 공이 분홍·하늘·흰 조각으로 깨진다 | 축소 |

엔진 한계: 원작 길은 좌우로 휘지만 이 엔진은 z축 직선 트랙이다. 휘는 길은 열을 비스듬히 옮겨 가는 길(계단식 차선 이동)로 흉내 낸다.

## 2. 물리 변경 (`sim.ts`, `constants.ts`)

모든 값은 여전히 정수(mm, mm/틱, 틱).

### 2.1 좌우 관성
- `SimState`에 `vx`(mm/틱) 추가.
- 매 틱: `want = clamp(floor((target - x) / LAT_K), ±VX_MAX)`, `vx += clamp(want - vx, ±LAT_ACC)`. `LAT_K = 5`, `LAT_ACC = 25`, `VX_MAX = 117`(7 m/s). 손을 떼면(목표 유지) 공이 목표에 부드럽게 멈춘다.
- 기울어진 판은 쌓이는 `drift`(mm, 정수, `initSim`에서 0)로 민다. 직전 틱에 바닥에 있었고 공 중심 칸(이동 전 x, 새 z)이 기울었으면 `drift += bank × BANK_DRIFT`, `drift`는 ±2·`X_LIMIT`에서 멈추고 **줄지 않는다**(판이 공을 옮긴 것이지 되돌아오는 용수철이 아니다). 실효 목표 `clampX(target + drift)`를 위 식의 `target` 자리에 쓴다. `BANK_DRIFT = 80`: 3칸 판 가운데에서 손을 떼면 속도 1단계에서 6행 판 안(약 4.8행)에 판 밖으로 밀려나고, 손가락을 위쪽으로 틱마다 80 mm(4.8 m/s, 키보드 `KEY_STEP` 117보다 느림) 옮기면 제자리를 지킨다.
- 손가락 목표는 ±`X_LIMIT` 안이라 `drift`가 크게 남으면 반대쪽 끝에 못 간다. 그래서 모든 템플릿은 `<` 행 수와 `>` 행 수가 같다(조각 안 속도가 같으므로 조각을 지나면 `drift`가 거의 0으로 돌아온다, 시드 5개 봇 4분 주행에서 기운 판 밖 잔여 최대 0.8 m — 가운데 5칸 끝 열 가운데까지 여전히 닿는다). 화면은 이어 하기 때 `target = clampX(x − drift)`로 시작한다.
- 옆면 막힘이면 `x`는 이전 값, `vx = 0`.

### 2.2 단차·급경사
- 급경사 `!`: 한 행에 −500 mm(약 27°). 최고 속도에서 한 틱 바닥 하강 ≈ 234 mm이므로 `DROP_TOL = 260`으로 올린다.
- 단차 `v`: 그 칸에서 열 높이를 −1000 mm(평평). 공은 떨어져 날다가 아래 판에 착지한다.

### 2.3 속도 = 터널 수
- `SPEED_STEP_DIST` 삭제. `speedLevel = max(s.speedLevel, course.boostsBefore(rowOf(z)))`. `boostsBefore(row)`는 시작 행이 `row` 이하인 터널 조각 수(**시작 터널 포함**). 원작처럼 시작 직후 '속도 증가'가 한 번 뜬다(첫 틱에 단계 1, 두 번 뜨지 않음).
- `SPEED_TABLE`: `V0 = 200`(12 m/s), 단계마다 ×1.06, 상한 `V_MAX = 467`(28 m/s). k번째 = `min(V_MAX, floor(200 × 106^k / 100^k))`, 상한에 닿은 뒤 1개까지.

### 2.4 블록 높이·기울기
- 칸에 선택 필드 `blockH`(mm, 기본 `BLOCK_H` 1000)와 `bank`(−1 왼쪽이 낮음 / +1 오른쪽이 낮음) 추가. 블록 충돌 높이는 `blockH`를 쓴다.
- 기울어진 판의 물리 바닥 높이는 칸 높이 그대로다(공 중심 기준). 기울기는 밀림과 화면에만 쓴다.

### 2.5 점수
- `score = min(SCORE_MAX, floor(tick / SCORE_TICKS))`, `SCORE_TICKS = 30`(0.5초에 1점). `SCORE_DIV` 삭제.
- 규칙이 바뀌므로 `logic.version = 2`.

## 3. 코스 변경 (`segments.ts`, `course.ts`)

### 3.1 DSL 추가 기호
| 기호 | 의미 |
|---|---|
| `!` | 급경사 내리막(이 행 −500 mm) |
| `v` | 단차(이 칸부터 열 높이 −1000 mm, 평평) |
| `<` / `>` | 평평한 기울어진 판. `<`는 왼쪽이 낮아 공을 왼쪽으로(`bank = −1`), `>`는 오른쪽으로(`bank = +1`) 민다 |
| `P` | 높은 기둥(바닥 + 블록, `blockH = 3000`) |
| `G` | 문 기둥(바닥 + 블록, `blockH = 2000`). 같은 행의 `G` 둘 사이에 화면용 가로대 |

좌우 반전 시 `<`·`>`는 서로 바뀐다(`bank` 부호 반전).

### 3.2 조각 종류
- `SegmentTemplate`·`ParsedSegment`·`SegmentInfo`에 `kind: 'tunnel' | 'descent' | 'obstacle'`. `decor: 'tunnel'`은 `kind: 'tunnel'`로 대체한다.
- 터널 조각: 가운데 5칸 `_`만(구멍·경사·단차·기울기·블록 없음), 길이 14~18행. 바닥에 가속 화살표, 양옆 마젠타 벽, 아치(화면).
- 내리막 조각: `!`·`\`·`v`로 크게 내려간다(조각당 −4 m 이상). 블록은 드물게.
- 장애물 조각: tier 1~4, 기존 종류 + 기둥·문·벽 통로(바깥 열 `B`/`P`로 3칸 통로)·1칸 레일·기울어진 좁은 판·비스듬히 옮겨 가는 길. 대체로 평평하거나 살짝 내려간다(`dh ≤ 0`).

### 3.3 생성 순서
- **단계** = 지금까지 지나온 터널 수(시작 터널 포함) = 그 구간의 속도 단계. 시작 터널 뒤가 단계 1.
- 첫 조각은 시작 터널(`START`, `kind: 'tunnel'`, 단계 1로 센다) → 내리막 → 장애물 `obstaclesInStage(단계)`개 → 터널 → 내리막 → … `OBSTACLES_BY_STAGE`: 단계 0~2는 1개, 3부터 2개. 녹화처럼 '속도 증가'가 약 7초마다(시드 5개 봇 첫 60초 간격 중앙값 6.5~7.6초, 테스트는 4~9초).
- 장애물 tier 가중치는 거리 대신 단계 기준: `TIER_WEIGHTS = [{ fromStage: 0, w: [1,0,0,0] }, { fromStage: 2, w: [3,1,0,0] }, { fromStage: 5, w: [2,2,1,0] }, { fromStage: 8, w: [1,2,2,1] }, { fromStage: 12, w: [1,1,2,2] }]`(단계가 짧아진 만큼 늦췄다).
- 터널·내리막은 각 풀에서 균등 추첨, 장애물은 최근 장애물 3개와 겹치지 않게(v1과 같음), 모든 조각 좌우 반전 동전.
- 조각 추첨 난수 소비는 조각마다 고정 개수(종류와 관계없이 3개)로 유지한다.

## 4. 화면 변경 (`render/`)

- **카메라**: x는 공 x와 같다(보간 없음). y만 부드럽게(낙하·단차 흔들림 방지). 평지에서는 공 뒤 4.2 m, 위 0.85 m, 시선은 눈→공 방향에서 고정 각만큼 위라 세로 화면에서 공이 화면 위에서 약 62% 지점에 온다.
- **내리막 카메라**(녹화 f_016·f_045·f_047·f_064·f_069·f_092): 내리막과 가속 직후에는 카메라가 뒤·위로 물러나 공이 화면 폭의 약 1/5로 작아지고 좁은 능선과 아래 낙차가 보인다. "내리막 정도" 0~1 = 공 열 바닥으로 잰 (공 뒤 3 m 안 가장 높은 바닥 − 공 앞 6 m 안 가장 낮은 바닥) / 3 m(`descentTarget`)와 가속 뒤 2.5초 동안 0.6에서 줄어드는 값(`boostPull`, 시작 터널 단계 1은 제외 — f_016은 가까운 리그) 중 큰 값. 시간 기준으로 보간(들어갈 때 3/s, 나올 때 0.8/s). 이 값으로 뒤 거리 4.2 → 7.0 m, 눈 높이 0.85 → 3.0 m, 세계 기준 최소 숙임 각 0 → 20°를 섞는다(`cameraRig`). 먼 리그로 평지를 보면 공이 약 0.57~0.6 지점(녹화 내리막 ≈0.60).
- **기울어진 판**: 판을 z축으로 ±20° 돌려 그린다.
- **터널**: 기존 아치 + 양옆 발광 마젠타 벽 + 바닥 하늘색 화살표(CanvasTexture).
- **가속 연출**: `speedLevel`이 오르면 2초간 공 뒤로 반투명 마젠타 빛줄기.
- **기둥·문**: 블록 높이는 `blockH`. 같은 행 `G` 둘 사이 위에 남색 가로대(윤곽 라벤더).
- **사망**: `hit`이면 공을 24개 안팎의 작은 정육면체(분홍·하늘·흰)로 바꿔 1초간 흩어지게 한다. `fall`은 v1처럼 계속 떨어진다.
- **색**: 바닥 남색(#333877 안팎) + 굵은 라벤더 격자선(#9ea2ff 안팎), 판 옆면 라벤더. 녹화와 나란히 놓고 맞춘다.

## 7. v3 변경(2026-11-19)

사용자 요청: "공이 굴러가는 모션 추가하고, 도로 너비를 최대 3으로 하고, 공 속도를 1.7배정도 빨리해". `logic.version = 3`(점수 식은 그대로, 시간 기준).

1. **굴러가는 공**: 공에 무늬 텍스처(`ballTexture`: 바탕 `BALL_COLOR` #c0109a + 밝은 분홍 #ff6fe2 경도 조각 넷 + 적도 띠, 광택·환경 맵 그대로). 매 프레임 보간한 공 중심 변위 (dx, dz)로 미끄러짐 없는 회전 사원수(`rollQuat`, 각속도 = 위 × 속도 / R)를 세계 기준으로 쌓는다 — 앞으로는 x축, 옆으로는 z축으로 구른다. 죽으면 멈춘다. 한 프레임 변위가 3 m를 넘으면(상태 교체) 굴리지 않는다.
2. **길 폭 최대 3칸**: 어느 행도 바닥 칸(블록·기둥·문 칸 포함)이 3개를 넘지 않는다(시작·터널·이음 포함, 테스트). 이음 행 `..___..`(열 −1..1), 이음·평평함 규칙도 가운데 3칸. 터널은 3칸, 벽 ±1.5 m, 가속 화살표 폭 2.4 m. 조각 안에서 3칸(또는 1~2칸) 길이 7열 위를 옆으로 옮겨 다니다가(원작의 휘는 길 흉내) 끝 이음에서 가운데로 돌아온다. 구멍 열은 높이가 그대로라 옆으로 옮겨 가는 건 모든 열이 같은 높이인 평지에서만 하고, 단차·경사는 가운데 3칸에서만 쓴다. 문은 3칸 길을 다 쓰는 `G_G`, 벽 통로는 1칸(`B_B`).
3. **속도 ×1.7**: `V0` 200 → 340, `V_MAX` 467 → 794 mm/틱. `SPEED_TABLE` = 340, 360, 382, 404, 429, 454, 482, 511, 541, 574, 608, 645, 684, 725, 768, 794, 794. `DROP_TOL` 260 → 440(급경사 최고 속도 한 틱 하강 ≈ 397 mm, 단차 1000은 여전히 난다). 옆 조작(`LAT_K`, `LAT_ACC`, `VX_MAX`, `BANK_DRIFT`)은 그대로라 행으로 잰 간격이 1.7배: 차선 변경 사이 빈 행 1칸 12, 2칸 21, 3칸 28, 1칸 틈 +5(구멍으로 좁아지거나 길이 옮겨 가는 행도 센다, 이음 행에서부터), 같은 쪽 기운 판 연속 13행 이하, 단차 뒤 평지 15행, 터널 24~30행, 시작 터널 40행. 오르막 끝 점프는 최고 속도에서 약 45행 날아 착지 평지를 50행 둔다. 화면은 앞 조각 145행, 안개 40~145 m(시간으로 v2와 비슷한 시야).

검증: 밸런스 게이트(모든 템플릿 × 반전 × 모든 속도 단계, 시드 5개 단계 12 통과), '속도 증가' 간격 중앙값 시드 5개 6.8~8.3초.

## 8. v4 변경(2026-11-21): 기믹

사용자와 정한 방향: 전진 속도는 고정(속도를 바꾸는 발판 없음), 첫 기믹은 **점프대**와 **좌우 왕복 블록**. `logic.version = 4`(점수 식 그대로).

**설계 원칙**: 전진 속도는 입력과 무관하다(공이 어떤 행에 닿는 틱은 코스만으로 정해진다). 그래서 길 전체를 시간에 따라 막는 기믹(열리고 닫히는 문 등)은 두지 않는다 — 어떤 위상에서는 통과할 방법이 없기 때문이다. 움직이는 장애물은 언제나 지나갈 칸을 남긴다.

1. **점프대 `J`**: 평평한 바닥 칸 + `pad: true`. 위아래 단계가 끝났을 때 바닥에 있고 공 중심 칸이 점프대면 `vy = JUMP_VY = 157`, `grounded = false`(이후 기존 중력·착지 규칙). 정점 1683 mm(1 m 블록은 넘고 3 m 기둥은 못 넘는다), 체공 약 44틱 — 1단계(360 mm/틱)에서 점프대 뒤 약 15행, 최고 속도에서 약 35행에 내린다. 공중의 공이 점프대 위를 지나면 아무 일도 없다. 반전해도 그대로, 터널·기운 판에는 없다.
   - 템플릿 규칙(테스트): 점프대는 그 행 길 전체(`..JJJ..`), 점프대 뒤 11행은 비행 구간(길 전체 구멍 — 모든 속도에서 14행까지 넘지만 8행만 쓴다 —, `BBB` 벽, 평지만), `BBB` 벽은 모든 속도에서 넘는 +7..+10행 중 +9행, +12..+42행은 같은 칸·같은 높이의 평평한 3칸 착지 평지. 지나갈 칸이 없는 행은 점프대 비행 구간에만 둔다.
2. **좌우 왕복 블록 `M`**: `..MMM..`처럼 정확히 3칸 이어진 그 행의 길 전체(파서가 강제, 2칸 행 금지). 바닥은 평지이고, 1 m 큐브(높이 `BLOCK_H`)가 바깥 `M` 칸 가운데 사이(2 m)를 오간다. 위치는 공용 순수 함수 `moverX(m, tick)`(`mover.ts`): 정수 사다리꼴 파형 — 양 끝에서 `MOVER_DWELL = 16`틱 멈추고 `MOVER_TRAVEL = 64`틱 동안 2 m를 옮겨 간다(약 31 mm/틱 — 공 옆 최고 117의 1/3 아래), 주기 `MOVER_PERIOD = 2·64 + 2·16 = 160`틱. 끝에서 멈추는 동안 빈 쪽이 바뀌지 않아, 큐브를 보고 반대쪽으로 옮겨 가는(차선 하나 18~21틱) 사람이 따라갈 수 있다(삼각파만이면 빈 쪽이 약 10틱 만에 뒤집혀 반응형 플레이어가 위상 128개 중 24~57개에서 죽었다). 3칸 길에서 큐브 한쪽에는 늘 1 m 이상 빈다.
   - 위상 = 조각 위상 + 조각 안 행 × `MOVER_ROW_OFFSET = 53`(mod 160). 조각 위상은 조각 추첨 셋째 난수(반전 동전)의 위 비트 `(r >>> 1) % 160` — 조각마다 난수 3개는 그대로. 반전은 x 범위 부호를 뒤집어 움직임도 정확한 거울상.
   - 충돌: 정지 블록과 같은 원–사각형 판정을 새 상태 틱의 큐브 x로 한다. 공 밑면이 `BLOCK_H` 위면 넘는다. `SimState`에 새 값은 없다(틱만 쓴다). `Course.moverAt(row) → { x0, x1, h, phase } | null`.
   - 템플릿 규칙(테스트): 앞뒤 26행(2칸 옮김 21 + 1칸 틈 5)은 같은 칸의 평평한 3칸 길만, 점프 착지 구간(+42행)과 그 뒤 26행 안에는 두지 않는다. 터널·급경사·단차 행에는 없다.
3. **새 장애물 조각**(tier 1은 기믹 없음): `j2-pad-gap`(점프대 → 구멍 8행), `m2-shuttle`(왕복 블록 하나), `j3-pad-wall`(점프대 → `BBB` 벽), `m3-narrow-shuttle`(2칸으로 좁아진 뒤 옮겨 간 3칸 길 위 왕복 블록), `m3-two-shuttles`(35행 떨어진 둘, 행 위상 95틱 ≈ 주기의 0.6 차이), `j4-islands`(점프대 → 구멍 → 37행 섬 → 점프대 → 구멍), `mj4-pad-shuttle`(점프대로 구멍을 넘고 한참 뒤 왕복 블록).
4. **밸런스 게이트**: 모든 템플릿 × 반전 × 모든 속도 단계, 왕복 블록 조각은 주기에 고르게 위상 16개(0, 10, …, 150)씩 더. 시드 5개 단계 12 통과, '속도 증가' 간격 테스트 그대로.
5. **화면**: 점프대는 노란 판(주황 갈매기 무늬)을 앞끝이 180 mm 솟은 쐐기로 그린다(낮은 카메라에서 얇은 판은 한 줄로만 보인다. 시뮬 바닥은 평평하고, 최고 속도에서도 공이 쐐기에 묻혀 보이지 않는 높이). 뜰 때 노란 고리가 0.45초 퍼진다. 왕복 블록은 주황 큐브(노란 가로띠) + 오가는 자리의 주황 바닥 선, 프레임마다 직전·지금 틱의 `moverX`를 alpha로 보간(`moverSceneX`).

사용자: "게임 템포가 너무 느려. 가만히 있어도 되는 부분이 너무 많아. (장애물이 나오는 빈도가 작고, 직선코스의 비율이 너무 높다는 뜻.)" `logic.version = 6`(점수 식 그대로, 코스가 달라진다).
