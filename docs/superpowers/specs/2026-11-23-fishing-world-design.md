# 펨타듀 낚시 — 넓은 세계 설계 (2026-11-23)

상태: **승인됨** (2026-11-23)

참고: 원작 장비·어종 정리는 프로젝트 문서 `specs/2026-11-23-stardew-fishing-reference.md`. 앞선 설계: `2026-11-23-fishing-design.md`(서버 권위 낚시), `2026-11-23-fishing-walk-design.md`(걸어 다니는 마을).

## 1. 의도

지금 펨타듀 낚시는 바닷가 마을 한 장, 어종 12종, 조건 없는 추첨, 움직임 하나뿐인 미니게임이다. 원작 스타듀 밸리 낚시의 네 축을 모두 들여온다.

1. **행동 유형**: 물고기마다 움직임이 다르다.
2. **장소별 어종**: 여러 지역 맵, 지역·자리마다 다른 물고기.
3. **찌**: 미니게임과 추첨 규칙을 바꾸는 장비.
4. **시간·계절·날씨**: 언제 던지느냐에 따라 다른 물고기.

여기에 사용자가 정한 진행 구조를 더한다: 돈으로 지역을 열고(다리·동굴 장비·배), 지역 도전과제를 깨면 그 지역 순간이동기를 쓸 수 있다.

사용자 동기: 원작 낚시를 제대로 즐길 수 있게, "어차피 언젠간 해야 할" 확장을 한 번에 설계한다. 친구들과 몇 주에 걸쳐 도감을 채우는 게임이 목표다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 지역 6곳(맵 6장), 어종 약 56종(일반 50 + 전설 6).
- 원작의 행동 유형 5종이 미니게임에서 눈에 띄게 다르게 느껴진다.
- 모두가 같은 게임 시계를 본다: 게임 하루 24분, 계절은 실제 1주, 날씨는 게임 하루마다.
- 찌 5종, 카본 낚싯대 1칸·명장 낚싯대 2칸.
- 지역 해금(돈), 지역 도전과제 6개, 순간이동기 6개.
- 전설 6종, 세이브당 각 1마리.
- 단계별 PR(§10). 각 단계가 그 자체로 플레이 가능하다.

**비목표**
- 낚시 레벨, 경험치, 물고기 등급(별), 보물상자, 미끼(소모품), 음파탐지 찌
- 통발, 야시장, 요리, 물고기 연못
- NPC, 건물 내부, 잠자기·체력
- 서버의 위치 추적 (화면이 알려 주는 지역·자리를 믿는다, §8)
- 다른 플레이어가 맵에 보이는 기능

**실패 조건 (동작해도 실패)**
- 원작의 그림·맵·아이콘·전설 이름을 베꼈다. (규칙·수치 참고는 괜찮다. 순간이동기 모양도 원작 오벨리스크와 닮지 않게.)
- 기존 세이브의 골드·낚싯대·가방·도감이 사라진다.
- 어떤 지역·자리·계절·시간·날씨 조합에서 던졌는데 걸릴 물고기가 없다.
- 순간이동기 도전과제가 특정 계절에만 깰 수 있어 몇 주를 기다려야 한다.
- 잡일이 탐험보다 커진다 (앞선 설계의 탐험 7 : 잡일 3). 소모품을 사러 오가거나, 상점 영업시간을 기다리는 일 같은 것.
- 화면 시계와 서버 시계가 눈에 띄게 어긋나, 화면에는 밤인데 서버는 낮 물고기를 준다 (몇 초 차이는 허용).
- 폰에서 맵 전환이나 밤 색조·비 효과 때문에 프레임이 눈에 띄게 끊긴다.

## 3. 접근 방식

**시간 흐름** (사용자 선택: B)
| | 방식 | 판단 |
|---|---|---|
| A | 실제 시간(KST) 그대로 | 여름 어종을 9개월 못 잡고, 늘 같은 시간대에 하면 못 보는 어종이 생김 |
| **B** | **빠른 게임 시계: 실제 1분 = 게임 1시간, 계절은 실제 1주** | **선택.** 짧게 들어와도 낮밤이 다 지나가고, 몇 주면 도감을 채움 |
| C | 낮밤은 실제, 계절은 주마다 | 시간대 어종의 문제가 A와 같음 |

**어종 규모** (사용자 선택: B, 원작 규모)
| | 방식 | 판단 |
|---|---|---|
| A | 3곳 약 30종 | 무난하지만 사용자가 원작 규모를 원함 |
| **B** | **6곳 약 56종** | **선택** |
| C | 바다만 12종 + 조건 | 장소별 어종이 사실상 없음 |

**지역 여는 방식** (사용자 선택: B + 순간이동기)
| | 방식 | 판단 |
|---|---|---|
| A | 처음부터 다 열림 | 돈 쓸 목표가 장비뿐 |
| **B** | **걸어서 잇되 일부는 돈으로 엶 + 도전과제로 순간이동기** | **선택.** 탐험과 성장 목표를 함께 줌. 처음 구상한 "배 사서 배낚시"가 들어감 |
| C | 지도 메뉴 순간이동만 | 걷는 맛이 줄고 B의 진행과 맞지 않음 |

**도전과제 형태** (사용자 선택: B)
| | 방식 | 판단 |
|---|---|---|
| A | 지역 어종 절반 도감 등록 | 단순하지만 지역마다 개성이 없음 |
| **B** | **조건 조합으로 지역마다 맞춤 과제 1개** | **선택.** 판정 틀 하나, 내용만 지역별 |
| C | 지역 전설 낚기 | 이동기가 너무 늦게 열림 |

**맵 구조** (사용자 선택: A)
| | 방식 | 판단 |
|---|---|---|
| **A** | **지역마다 맵 한 장, 가장자리 출구로 전환** | **선택.** 지금 타일맵·캐시를 맵마다 재사용, 폰 메모리에 맵 한 장만 |
| B | 전부 이어진 큰 맵 하나 (150×100칸 안팎) | 통째 캐시가 폰에서 무겁고 조각 그리기를 새로 짜야 함 |
| C | 맵 여러 장 + 지도 화면 이동만 | 걸어서 잇는 B안 진행과 맞지 않음 |

**전설** (사용자 확인): 세이브당 1마리. 반복 가능하게 하면 비싼 전설이 돈벌이가 되어 가격·확률을 따로 맞춰야 한다.

**어종 조건 판정**: 다른 방식이 없다. 어종 데이터에 조건을 적고, 서버가 던질 때 `now`로 계산한 시각·계절·날씨와 화면이 알려 준 지역·자리로 후보를 걸러 추첨한다.

## 4. 게임 시계 (`src/games/fishing/clock.ts`, 순수 함수, 브라우저·Deno 공용)

- 기준은 KST(UTC+9, 서머타임 없음). `kstMs = nowMs + 9h`.
- **시각**: 실제 1초 = 게임 1분. `gameMinute = floor(kstMs / 1000) mod 1440` (0~1439). 24분은 하루 1440분을 나누므로 KST 자정마다 게임 0시가 된다.
- **게임 날짜**: `gameDay = floor(kstMs / 1440000)` (실제 24분마다 1 증가).
- **계절**: `season = SEASONS[floor((kstMs - ANCHOR) / 1주) mod 4]`, `SEASONS = ['spring','summer','autumn','winter']`. `ANCHOR`는 월요일 0시(KST) 하나로 고정한다. **2026-11-23(월) 0시 KST 주가 봄**이 되게 둔다(빌더가 배포 주에 맞춰 바꿔도 된다. 바꾸면 이 문서를 고친다).
- **날씨**: 게임 날짜마다 `weather(gameDay)` → `'sun' | 'rain'`. 정수 해시(예: 32비트 섞기 함수)로 결정하며, 같은 `gameDay`면 서버·화면이 같은 값. 비 확률 25%. 겨울의 `'rain'`은 화면에서 눈으로 그린다(출현 조건에서는 비와 같다).
- **시간대**: "밤"은 20~5시(도전과제 `night`도 같음). 어종 조건은 게임 시각 구간 `[from, to)`(시, 0~24, 자정을 넘는 구간 허용, 예: 18→2)으로 쓴다. 화면의 밤 색조: 18~20시 어스름, 20~5시 밤, 5~6시 새벽.
- **조건 묶음**: `conditionsAt(nowMs) → { gameMinute, gameDay, season, weather }`.
- **화면 동기화**: world 응답의 `server_now`로 `offset = server_now - Date.now()`를 잡고, 화면 시계는 `Date.now() + offset`. 응답마다 갱신한다.
- **HUD**: 장면 위쪽(기존 `hudSide` 자리 규칙 따름, 낚시 트랙 반대쪽)에 계절 아이콘·날씨 아이콘·시각(10분 단위, `14:30`). 글자도 아이콘도 직접 그린 픽셀 스프라이트(숫자 4×6)로 정수 좌표에 찍는다(fillText 없음). 터치에서는 캔버스 위쪽 안내 줄 아래에 두어 낚시 내내 보이게 한다.

## 5. 어종

### 5.1 데이터 형식 (`data.ts`)

```ts
type Behavior = 'mixed' | 'smooth' | 'dart' | 'floater' | 'sinker'
type Species = {
  id: string; name: string; rarity: 'common' | 'uncommon' | 'rare' | 'legend'
  basePrice: number; minCm: number; maxCm: number
  difficulty: number      // 0~1 (원작 난이도 15~110을 대략 /110)
  behavior: Behavior
  area: AreaId            // 한 어종은 한 지역 (예외 필요하면 배열로 바꿔도 됨, 빌더 재량)
  spots?: string[]        // 없으면 그 지역 모든 자리
  seasons?: Season[]      // 없으면 사계절
  hours?: [number, number] // 없으면 하루 종일
  weather?: 'sun' | 'rain' // 없으면 무관
  minRod: 1 | 2 | 3 | 4
}
```
전설은 같은 형식에 `legend: { power: number }`(최소 던지기 강도, 0.95 = "최대 강도")를 더한다.

### 5.2 추첨 (`rollCatch` 확장)

1. 전설 판정: 현재 지역·자리·계절·시각·날씨·강도·낚싯대가 어떤 전설의 조건을 모두 만족하고 그 전설을 아직 안 잡았으면, 확률 `LEGEND_CHANCE`(시작값 0.08)로 그 전설.
2. 아니면 낚싯대 가중치로 등급(common/uncommon/rare)을 뽑고, 그 등급에서 조건을 만족하는 어종 중 균등 추첨. **그 등급에 후보가 없으면 아래 등급으로 차례로 내려가고(common까지), 그래도 없으면 위 등급**으로 옮긴다.
3. 크기·입질 지연은 지금 식 그대로(부두 보너스 포함).
- 낚싯대 가중치에서 `legend` 항목은 없앤다(전설은 1단계에서만).
- rng 호출 순서를 문서화하고 테스트로 고정한다.
- **보장 (테스트)**: 모든 지역 × 자리 × 계절 × 시간(1시간 단위) × 날씨 조합에서, 대나무 낚싯대(1단계)로 common 후보가 최소 1종.

### 5.3 지역별 구성 (초안 — 이름·수는 바꿔도 되고, 조건은 빌더가 아래 규칙에 맞춰 정한다)

| 지역 | 자리 | 일반 어종 | 전설 (조건 초안) |
|---|---|---|---|
| 바닷가 마을 `village` | `pier`, `shore` | 기존 11종(멸치·망둥어·전갱이·고등어·숭어·우럭·도다리·오징어·참돔·농어·방어) + 문어·갈치·복어·붕장어 = 15 | 다금바리: 부두, 겨울, 최대 강도 |
| 마을 강 `river` | `river` | 피라미·갈겨니·누치·꺽지·은어·쏘가리·메기·뱀장어 = 8 | 황금 쏘가리: 여름, 비, 최대 강도 |
| 숲 `forest` | `pond`, `waterfall` | 붕어·잉어·미꾸라지·가물치·블루길(연못), 버들치·열목어(폭포) = 7 | 백년 가물치: 연못, 봄, 밤 |
| 산 호수 `lake` | `lake` | 빙어·무지개송어·산천어·큰입배스·강준치·향어·철갑상어 = 7 | 은빛 대왕송어: 가을, 새벽(4~7시), 최대 강도 |
| 동굴 `cave` | `cave1`, `cave2`, `cave3` (얕은 곳→깊은 곳) | 가상 어종 6 (예: 장님고기·돌가재어·수정치어·박쥐메기·용암장어·불꽃잉어, 깊을수록 비싸고 어려움) | 화룡어: 가장 깊은 곳, 계절·날씨 무관, 최대 강도 |
| 섬 `island` | `sea`, `lagoon` | 흰동가리·나비고기·쏠배감펭·청줄돔·곰치·가오리·만새기 = 7 | 무지개 청새치: 바다, 맑은 날, 정오(11~14시), 최대 강도 |

**조건 규칙**
- 기존 12종은 id를 그대로 둔다 (세이브의 도감·가방 유지). 가격·크기는 그대로, 조건·행동 유형만 새로 붙인다.
- 지역마다: 사계절 상시 common 2종 이상, 밤에만 나오는 어종 1종 이상, 비에만 나오는 어종 1종 이상(동굴은 시간·날씨 무관 지역이라 제외), 행동 유형 3가지 이상.
- 동굴은 계절·시간·날씨 조건을 쓰지 않는다 (원작 광산처럼 언제나 같음). 섬은 계절 조건을 쓰지 않는다 (원작 진저섬처럼).
- 가격대는 지역 해금 비용과 함께 오른다: 마을·강·숲 < 산 호수 < 동굴 < 섬. 원작 가격 비율을 참고한다.
- 난이도·행동 유형은 원작에서 비슷한 어종 값을 참고한다 (참고 문서 §3).
- 전설: `minRod` 3 이상(동굴·섬 전설은 4). 기본가는 원작 전설 수준(900~5,000G를 우리 경제에 맞춰), 난이도 0.8~1.0.

### 5.4 도감 화면
- 지역 탭으로 나눈다. 안 잡은 어종은 실루엣 + 지역만, 잡은 어종은 이름·최대 크기·마릿수 + 출현 조건(자리·계절·시간·날씨) 표시. 전설은 테두리나 표식으로 구분하고 잡았는지 표시.
- 프로필 기록 `dex`의 `detail`은 `잡은 수/전체`(전체 = 전설 포함 전 어종).

## 6. 미니게임 행동 유형 (`minigame.ts`, 화면 전용)

`BarParams`에 `behavior`를 더하고, 물고기 목표 고르기·이동을 유형별로 바꾼다. 수치는 빌더 재량, 느낌은 다음을 따른다.

| 유형 | 느낌 |
|---|---|
| mixed | 지금 움직임 그대로 |
| smooth | 목표를 드물게 바꾸고 부드럽게 가감속. 같은 난이도에서 가장 쉬움 |
| dart | 짧은 간격으로 크게 튐. 같은 난이도에서 가장 어려움 |
| floater | 목표가 막대 위쪽으로 치우침, 위에 머무는 시간이 김 |
| sinker | 목표가 막대 아래쪽으로 치우침, 바닥에 머무는 시간이 김 |

- 서버는 미니게임을 검증하지 않는다(지금과 같다: 최소 싸움 시간과 성공·퍼펙트 신고만).
- 테스트: 같은 난이도·같은 rng 열에서 유형별 물고기 위치 분포가 위 느낌대로(예: floater 평균 위치가 위쪽, dart 이동량 > smooth 이동량).

| id | 이름 | 효과 | 적용 | 시작 가격 |
|---|---|---|---|---|
| `cork` | 코르크 찌 | 낚시 바 길이 +20% (낚싯대 보너스와 곱) | 화면 | 1,000G |
| `trap` | 함정 찌 | 물고기가 바 밖일 때 진행도 감소 속도 −50% | 화면 | 1,500G |
| `barbed` | 가시 바늘 | 물고기가 바 안에 있으면 바가 물고기 쪽으로 끌림 | 화면 | 2,000G |
| `spinner` | 회전 찌 | 입질 지연 ×0.7 | 서버 | 1,500G |
| `curious` | 호기심 찌 | rare 가중치 ×1.5, 전설 확률 ×1.5 | 서버 | 5,000G |

- 칸: 낚싯대 1·2단계 0칸, 3단계(카본) 1칸, 4단계(명장) 2칸. 같은 찌 두 개는 못 낀다.
- 한 번 사면 영구, 소모 없음. 상점에서 산다.
- 장착 변경은 낚시 중이 아닐 때(`pending` 없음) 가방/장비 메뉴에서. 서버 행동 `equip`.
- 화면 효과 찌도 장착 목록은 서버 상태에 있고, 화면은 view의 장착 목록으로 미니게임 매개변수를 정한다.

## 8. 지역·이동·도전과제

### 8.1 지역과 맵
- 지역 id: `village`, `river`, `forest`, `lake`, `cave`, `island`. 맵마다 `MapDef`:
  - 타일 행(문자열, 지금 형식), 크기(맵마다 달라도 됨, 대략 40×30~56×40)
  - `exits`: 가장자리 출구 구간 → 도착 지역과 도착 지점
  - `teleporter`: 순간이동기 위치(2×2칸 정도의 구조물) 와 그 앞 서는 자리
  - `world`: 세계 지도 위 맵의 원점(칸). 순간이동 거리 계산용
  - 낚시 자리 판정: 물 타일 종류 + 서 있는 타일로 `spot`을 정한다 (마을의 `pier`/`shore` 규칙을 일반화). 새 타일 종류: 강물, 연못물, 폭포, 동굴 바닥·벽·물, 용암, 섬 모래·야자수·산호 바다 등.
- 연결 (초안): 마을 ↔ 강(북쪽), 강 ↔ 숲(서쪽), 강 ↔ 산 호수(북쪽, 무너진 다리), 숲 ↔ 동굴(동굴 입구, 막힘), 마을 부두 → 섬(배). 빌더가 맵을 그리며 바꿀 수 있다.
- 전환: 출구 칸에 들어서면 화면이 잠깐 어두워졌다(약 300ms) 도착 맵의 도착 지점에 선다. 맵 정적 캐시는 현재 맵 하나만 유지하고 전환 때 갈아 끼운다.
- 위치 저장(`position.ts`)에 지역을 더한다. 저장된 지역이 열려 있지 않거나 자리가 막혀 있으면 마을 시작 위치.

### 8.2 지역 해금
| 지역 | 처음 상태 | 여는 방법 | 시작 가격 |
|---|---|---|---|
| 마을·강·숲 | 열림 | – | – |
| 산 호수 | 무너진 다리가 길을 막음 | 다리 앞에서 행동 → 수리 | 5,000G |
| 동굴 | 입구가 돌무더기로 막힘 | 입구 앞에서 행동 → 동굴 장비 | 15,000G |
| 섬 | 마을 부두 끝 선착장 | 선착장에서 행동 → 배 구입. 이후 선착장에서 행동하면 무료로 섬 ↔ 마을 왕복 | 50,000G |

- 서버 행동 `unlockArea { area }`: 아직 안 열린 해금 지역이고 골드가 충분하면 연다. 화면은 막힌 출구 앞에서 가격과 구매 버튼을 보여 준다.
- 서버는 위치를 모른다. `cast`의 `area`가 열린 지역이 아니거나 `spot`이 그 지역의 자리가 아니면 거절(`bad_area`/`bad_spot`)하는 것으로 충분하다.

### 8.3 도전과제
- 지역마다 하나. 판정 틀 하나:
```ts
type Challenge = {
  id: string; area: AreaId; title: string; desc: string; count: number
  filter: { species?: string[]; spot?: string; perfect?: true; weather?: 'rain'; night?: true; minSizePct?: number; distinct?: true }
}
```
  `distinct`면 서로 다른 어종 수를 센다. 판정은 `resolve` 성공 때, **던질 때 저장해 둔 조건**(지역·자리·계절·시각·날씨)으로 한다. 그래서 `Pending`에 던질 때의 `area`, `spot`, `cond`를 저장한다.
- **규칙: 어떤 계절에도 깰 수 있어야 한다** (계절 한정 어종을 요구하지 않는다). 비 조건은 괜찮다(게임 하루 24분 중 25%).
- 초안:
  - 마을: 부두에서 퍼펙트로 3마리
  - 강: 비 오는 날 강에서 아무거나 5마리
  - 숲: 폭포에서 3종 이상
  - 산 호수: 밤에 5마리
  - 동굴: 가장 깊은 곳(`cave3`)에서 5마리
  - 섬: 크기 상위 30%(`minSizePct: 0.7`) 물고기 3마리
- 진행은 배포 뒤부터 센다(과거 기록 소급 없음). 깬 과제는 되돌아가지 않는다.
- 프로필 기록에 `challenges`(깬 수, detail `n/6`)를 더한다. manifest `records`와 기록 테이블 규칙을 따른다.
- 화면: 도전과제 목록(진행도 포함)을 메뉴에서 볼 수 있다. 깨는 순간 알림.

### 8.4 순간이동기
- 지역 도전과제를 깨면 그 지역 순간이동기가 열린다. 열린 이동기 앞에서 행동하면 열린 다른 이동기 목록과 요금이 뜬다.
- 요금: `fee = TP_BASE + ceil(dist / 10) * TP_PER_10`. `dist` = 두 이동기의 세계 좌표(맵 `world` 원점 + 이동기 위치) 사이 직선 거리(칸). 시작값 `TP_BASE = 30`, `TP_PER_10 = 1`. 섬은 세계 지도에서 멀리 둬서 비싸게.
- 서버 행동 `teleport { from, to }`: 둘 다 열림, 서로 다름, `pending` 없음, 골드 충분 → 요금 차감. 결과로 화면이 도착 맵의 이동기 앞에 캐릭터를 놓는다.
- `from`은 화면이 알려 주는 값을 믿는다. 다른 이동기 앞이라고 속여 요금을 덜 낼 수 있지만 친구끼리 게임이라 감수한다.
- 순간이동기는 원작 오벨리스크와 다른 독자 디자인 (예: 등대 모양 신호기 — 빌더 재량).

### 8.5 상점
- 상점은 마을에만, 시간과 관계없이 항상 연다. 판매·낚싯대·가방·찌. 먼 지역에서 가방이 차면 걸어오거나 순간이동해서 판다 (순간이동기의 쓸모).

## 9. 서버 상태와 이전

`State`에 더하는 것:
```ts
areas: AreaId[]            // 열린 지역. 기본 ['village','river','forest']
tackles: TackleId[]        // 산 찌
equipped: TackleId[]       // 장착, 길이 ≤ 낚싯대 칸 수
challenges: Record<string, { progress: number; seen?: string[]; done: boolean }>
legends: string[]          // 잡은 전설 id
pending: Pending & { area: AreaId; spot: string; cond: Conditions; power: number }
```
- 행동: `cast { area, spot, power }`(지금 `area: 'pier'`, `spot` 선택 형식을 바꿈), `hook`, `resolve`, `sell`, `buyRod`, `buyBag`, `buyTackle { id }`, `equip { ids }`, `unlockArea { area }`, `teleport { from, to }`.
- 전설 잡기는 `resolve` 성공 때 `legends`에 더한다. 놓치면 다시 기회가 있다.
- **이전 (`migrate`)**: v2 세이브 → 골드·누적·낚싯대·가방 단계·가방·도감 유지. `areas`는 기본 3곳(옛 `'pier'`는 버림). 도감에 `grouper`가 있으면 `legends`에 `grouper`를 넣는다. 나머지는 기본값.
- `logic.version`: 판정·추첨·저장 형식이 바뀌는 단계마다 올린다(1단계에서 3). `migrate`는 v2→v3→v4…로 이어지게 짠다. 1단계에서 기본 `areas`에 강·숲이 들어가도 맵이 없으니 화면이 보내지 않는다. 매 단계 `world` 함수 재배포가 필요하다(`data.ts`·`logic.ts`·`clock.ts`가 번들에 들어감).
- 응답 크기: view에 전체 어종 표가 들어가지 않게 한다(어종 표는 화면도 `data.ts`를 import).

## 10. 구현 단계 (PR 단위, 각 단계가 플레이 가능)

1. **시계·날씨·행동 유형·조건 판정**: `clock.ts`, 어종 형식 확장, 추첨 개편(조건·등급 대체·전설 판정 틀), 기존 12종에 조건·유형 부여 + 마을 새 어종 4종(문어·갈치·복어·붕장어)(마을 한 장), 미니게임 유형, HUD 시계, 밤 색조, 비·눈 효과. 다금바리를 조건 전설로.
2. **맵 여러 장**: `MapDef` 일반화, 출구 전환, 위치 저장에 지역, 강·숲 맵과 어종 15종 + 전설 2종, 도감 지역 탭.
3. **지역 해금**: `unlockArea`, 다리·동굴 입구·선착장/배, 산 호수·동굴·섬 맵과 어종 20종 + 전설 3종.
4. **도전과제·순간이동기**: 과제 판정·목록·알림, 이동기 구조물·목록·요금, 프로필 기록 `challenges`.
5. **찌**: 상점·장착 메뉴, 서버 효과 2종, 화면 효과 3종.
6. **마무리**: 경제 수치 조정, 전설 표시 다듬기, 배포 체크리스트 갱신.

단계마다 배포 체크리스트(`docs/deploy-checklist.md`)에 수동 확인 항목을 더한다.

## 11. 제약
- 프로젝트 규칙(`CLAUDE.md`) 그대로: 화면 문구 한국어, 모바일 우선, 캔버스 안 색은 예외지만 HTML 메뉴는 theme 토큰만, `logic.ts`·`data.ts`·`clock.ts`·`map` 데이터는 순수·외부 의존 없음·상대 import에 `.ts`.
- 그림은 전부 직접 그린 16px 픽셀 아트(`sprites.ts` 형식). 새 물고기 약 44종, 새 타일, 순간이동기, 다리·돌무더기·배, 날씨 아이콘.
- 서버 권위: 골드·도감·해금·찌·과제·전설은 서버 상태만 바꾼다. 미니게임·걷기·지역/자리 신고는 화면을 믿는다.
- 폰 성능: 정적 캐시는 현재 맵 하나. 비·눈 입자 수 상한, 밤 색조는 한 번의 채우기.
